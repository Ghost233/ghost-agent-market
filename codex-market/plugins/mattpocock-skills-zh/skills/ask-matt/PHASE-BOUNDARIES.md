# 阶段边界

**阶段**是会话中的一块工作，例如追问、实现、QA。定义刻意保持宽松：当你认为“好了，这部分完成了”时，阶段结束。

**阶段边界**是两个阶段之间的空隙，也是唯一应该作出以下决策的位置。阶段中途无需选择：继续，或把剩余工作拆给子代理。中途 compact 会让代理丢失思路。

## 五种选择

| 选项         | 作用                                                            |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在当前会话，完全不切换上下文。                                  |
| **`/clear`** | 清空上下文窗口，从零开始。                                        |
| **`$handoff`** | 编写可移植 Markdown，并用它在任意位置启动会话。                  |
| **Subagent** | 把任务发送到独立上下文窗口并取回报告。                              |
| **`/compact`** | 压缩当前上下文，用摘要启动新会话。                              |

## 决策树

在边界从上到下判断，第一个回答**是**的分支获胜。

**1. 能否在当前会话继续？** 两种情况回答是：下一阶段需要把本阶段作为**一手来源**，或剩余 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）足以容纳下一阶段。追问 → 实现是标准例子：实现需要原始推理，而非摘要。Continue 无成本也无损失，因此首先判断。

**2. 当前上下文与下一阶段无关吗？** 如果探索、决策和死路都可以丢弃，选择 **`/clear`**。这是成本最低的操作，不耗时间并返还整个窗口；旧会话仍可恢复。

误判的代价不可逆。清除*相关*上下文会失去实现背后的**原因**，无论怎样重读 diff 都无法找回。

**3. 是否需要交接？** `$handoff` 适用范围很窄，只用于：

- 切换到**新执行环境**（Claude → Codex）；
- 移动到**新目录**或仓库；
- 把工作交给**同事**；
- 在不打断当前工作的前提下，分叉**阶段中途**发现的旁支任务。

除此之外不要使用。`$handoff` 购买的是**可移植性**，即能够移动的文件；没有内容需要移动时就不需要它。

**4. 任务能否离线完成？** 如果范围足够严格，无需人在键盘前指导，就交给**子代理**，当前会话保持不变。自动化审查是标准例子：代理读取 diff 并报告，期间无需用户参与。

**5. 否则选择 `/compact`。** 上下文相关、执行环境和目录不变、用户仍需参与时，决策树经常落到这里。传入说明（如 `/compact 接下来要 QA 这个区域`），让摘要保留下一阶段所需内容。

`/compact` 是**默认结果，不是第一选择**。它位于底部，因为上方四个问题都更便宜或更精确。一开始就 compact，可能产生一个对摘要压平的决策抱有错误自信的新会话。

## 一手与二手来源

除 **Continue** 外，每种操作都会把**一手来源**变成**二手来源**，即用摘要替代原始会话。取舍始终如下：

| 来源                              | 信息量 | 噪音 | 可用空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（Continue）                  | 完整   | 多   | 少       |
| 二手（`/compact`、`$handoff`）    | 有损   | 少   | 多       |

因此问题 1 必须最先。只有留下的成本高于收益时，才承担信息损失。

## 这些都需要判断

这些问题并非完全客观，每个都包含取舍，同一边界在不同时间可能作出不同选择。价值在于只在边界、并且**按顺序**提问，而不是在工作中途提问。
