# 交互式向导

**向导**是一个 Bash 脚本，逐步引导人类完成手工操作。这类操作亲手执行很繁琐，每次重新向 AI 解释也很繁琐。向导会打开每个 URL，准确说明要点击和复制什么，捕获相应值，将其写入正确位置（如 `.env`、GitHub secrets），在每个阶段请求确认，并显示剩余阶段数。它可以配置第三方服务、执行一次性迁移，或把项目从一种状态切换到另一种状态。

[template.sh](template.sh) 已经解决了良好体验所需的能力：逐阶段进度、确认关卡、跨平台打开 URL（包括 WSL）、隐藏式 secret 输入、幂等的 `.env` 更新、写入 `gh secret`/`gh variable`，以及最终总结。**你的工作仅限于界定流程范围并编写各个阶段。** 每个向导中 `STAGES` 标记上方的库代码都完全一致；一致性正是它的价值所在，绝不手工修改。

向导默认是临时产物：为一次运行而创建，保存到临时路径或 `scripts/`，工作完成后删除。只有当用户希望仓库长期保留一条可重复执行的设置路径时，才提交它。

## 流程

### 1. 界定流程范围

梳理人类必须执行的每个手工步骤，以及过程中需要捕获的每个值。先阅读仓库，不要在缺乏背景时直接提问：

- 对于环境设置：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`。每个 `secrets.*`/`vars.*` 引用都是向导必须生成的值。
- 对于迁移或切换：明确当前状态、目标状态，以及两者之间不可逆的操作。

随后向用户展示按顺序排列的阶段列表及每个阶段产生的值，并请求确认。用户可以添加、删除或调整顺序。

**完成标准：** 每个阶段都已按顺序命名；对于每个捕获值，你都知道：(a) 人类从哪里获得它；(b) 它写入哪里（`.env`、GitHub secret、两者都有，或不写入任何位置——某些阶段只有操作）；(c) 它是 secret（隐藏输入）还是公开值。

### 2. 绘制每个阶段的操作路径

为每个阶段写出人类遵循的精确路径：打开哪个 URL、在那里执行什么操作、值显示在哪里、填入哪个变量。例如：“Dashboard → Developers → API keys → Reveal test key → copy”。如果你并不确定当前 UI 或准确命令，要明确说明并询问用户或查阅文档；绝不虚构可能不存在的步骤。

**完成标准：** 每个阶段都能追溯到陌生人也可照做的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按照依赖顺序，用每个步骤对应的一个 `stage` 替换示例阶段。使用库提供的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`，并将 `TOTAL_STAGES` 设置为所编写的阶段数。

遵守模板设定的标准：先打开 URL，再请求相应值；所有 secret 都使用 `ask_secret`；每个需要持久化的值都调用 `write_env`；只有 CI 确实需要的值才调用 `set_secret`；任何不可逆操作前都调用 `confirm`。每个 `stage` 都会清屏，只显示当前步骤；每个阶段只安排一个聚焦任务，避免用户需要的信息滚出屏幕。不要修改标记上方的库代码。

### 4. 验证并交付

- 运行 `bash -n <script>`；如果存在 `shellcheck`，也运行它。
- 运行 `chmod +x <script>`。
- 不要自行端到端运行脚本，因为它会打开浏览器并等待人类输入。改为静态追踪：步骤 1 中的每个值都已被捕获并写入约定位置，每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全一致。
- 告诉用户如何运行。如果这是一条可重复执行的设置路径，则提交脚本，并从 README 链接它，让下一个人直接运行脚本，而不是再次询问 AI。
