# 本地 worktree 交付（覆盖上游 PR 步骤）

本文件优先于 Matt 的 implement-spec 中有关 PR 的步骤。保留其任务图、frontier 调度、子代理角色和代码审查流程；不创建、更新或合并 PR，不依赖 PR 编号，也不自动关闭远程 issue。

1. **确定集成位置。** 使用用户指定的本地目标分支及其已有 worktree；未指定时使用用户当前分支和当前工作区作为集成 worktree，记录起始 commit 作为本轮审查基线。不额外创建 PR 分支或临时集成分支。遵守仓库对分支/worktree 的约束；若约束阻止必要操作，说明具体冲突。
2. **隔离实施。** 每个 implementer 在自己的任务分支和 worktree 中工作，记录其基线、工单和路径。新解锁的工单从已集成其依赖的提交启动；依赖仅在成功集成后才视为解除。exploration 与 review 只读访问所需 worktree，不并发修改集成工作区。
3. **串行集成。** 每个 implementer 返回提交、测试结果和剩余问题后，由唯一 merger 在集成 worktree 串行合入已提交的任务分支。可 fast-forward 时优先使用；分叉时以普通 merge 保留提交历史，不以 rebase、cherry-pick 或 reset 制造同步。冲突处理与跨工单验证完成后再解锁下游工单，不能把“子代理开发完成”当作“已集成”。
4. **审查与修复。** 全部工单集成后，对“起始 commit → 当前集成提交”执行平台对应的 code-review，明确使用本地提交范围，无需 PR。单个 implementer 在修复 worktree 完成审查修复，再由 merger 合入并运行受影响的验收/回归检查。
5. **本地交付。** 以工单完成情况、集成分支完整 commit hash、测试与审查结果、未解决事项作为交付结果，替代“PR 可供审查”。目标本地分支必须实际包含全部交付提交；若用户工作区尚未同步，只允许 fast-forward，完成前核对工作区、分支与提交。push 仅在用户授权时执行；推送后核对本地和远端 hash 一致。
6. **清理。** 只移除本轮创建、改动已完整合入且工作区干净的任务/修复 worktree。保留用户集成 worktree；不强制删除，不自动 stash、移动、覆盖或清理用户未提交/未跟踪文件。遇到阻塞保留现场，并报告尚未集成、未同步或未清理的路径及原因。
