# Ghost Matt Test Report

平台差异：按用户要求，本版先在 Codex 试用并验证；Claude Code / ZCode 保留旧流程，验证后再同步，因此本技能暂仅发布于 Codex。

对照规格、任务与已有证据汇报覆盖和测试状态；不运行测试，不启动开发或修改代码。

沿用项目已有规格、工单和报告位置；没有约定时可查找 `docs/specs/<主题>/spec.md`、同主题的 `tickets/` 和 `progress.md`。沿用稳定的 AC 验收编号、T 工单编号及规格修订，不因生成报告重建或改写任务。

简单报告由主线程直接完成；清单较大时可委派一个只读盘点代理。使用子代理时，调用 `collaboration.spawn_agent`，指定 `agent_type: "worker"`、`model: "gpt-5.6-terra"`、`reasoning_effort: "xhigh"`、`fork_turns: "none"`；宿主无法提供这些参数时说明限制，不静默换模型或声称已经委派。 给代理提供范围、文档指针、当前内容版本及相关原始日志，明确只读边界。

## 1. 定位证据

读取用户指定的规格、全部相关工单、当前进度与最近报告。缺少规格或工单时仍汇总可用运行结果，标明无法计算需求覆盖；缺少测试结果时列待验证项，不触发重测。

可以委派一个只读代理盘点较大清单，提供相关原始日志、版本和上下文指针。简单报告直接完成。范围不明才询问，不能静默缩小到已有绿灯部分。

## 2. 建立映射

逐项提取 AC 与任务验收条件，包括尚无测试的要求；重复项去重并保留来源。映射正式用例、测试套件或明确人工验收证据，不凭名称相近推定覆盖，也不添加想象中的必测项。

优先使用当前候选的最新证据。核对实际源码/构建来源；旧版本、相关内容已变或来源不明的结果标为历史/待验证，不计入当前已通过。按影响判断证据是否仍有效，无关文档变化不机械作废业务测试。

区分通过、失败、跳过、未运行、阻塞、未知、历史/待验证和缺少对应测试。区分断言失败与未启动/收集失败/超时。零用例不算通过，没有明细时只报告 runner 的原口径。

## 3. 汇报

注明范围、规格修订、代码版本和证据时间，再用表格呈现：

| AC / 工单 | 测试内容与层级 | 覆盖情况 | 当前结果 | 命令/版本/日志 | 缺口或阻塞 |
| --- | --- | --- | --- | --- | --- |

覆盖率：完整映射到可执行测试或明确人工验收步骤的 AC 数 / 全部唯一 AC 数。验收通过率：全部对应检查有当前通过证据的 AC 数 / 全部唯一 AC 数。用例通过数单独按 runner 口径列出，不能把 AC、测试文件和用例混加。

分母包含未实现、未运行和阻塞的范围内验收项；清单不完整时不报精确总通过率。部分条件通过不使整个 AC 通过。条目多可分组汇总并附完整明细位置，不能丢掉失败项；未关联规格的已有测试单列。

最后列全部失败、覆盖缺口、阻塞与待验证项。主线程核对口径后交付报告；建议下一步不构成运行授权。
