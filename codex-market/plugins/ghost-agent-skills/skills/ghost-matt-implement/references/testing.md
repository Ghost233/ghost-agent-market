# 整轮测试与证据

在已确定的测试范围内执行一轮并保留证据。本参考不授予修改代码的权限；是否进入修复由用户授权和技能主流程决定。

## 准备一轮

确定用户指定范围与规格验收范围，不把“运行一个测试”扩成全仓。要求“全部测试”时盘点全部适用入口，包括构建内嵌的测试，避免重复计算或重复运行。记录入口、实际覆盖、依赖产物、共享资源、超时和执行顺序；已有明确命令直接复用。

测试前检查选择器、工具及依赖是否存在，入口是否首败退出。独立套件用现有 no-bail 机制或逐项执行、汇总退出码；不能用 `|| true` 丢弃失败。没有继续入口时标明受阻范围，独立运行测试不擅自改 runner；开发流程在本轮结束后将此列为测试编排修复。

完整验收前停止相关代码写入，记录各仓库分支、HEAD、未提交内容及实际构建来源。允许验证未提交候选，但须保留可辨认的差异/内容指纹及必要未跟踪源码清单，不能只用 HEAD 冒充来源。脚本只构建 `git archive HEAD` 时，确认当前修改已进入被测候选；没有提交授权时选择支持当前内容的入口或报告限制。

依赖测试产物的任务待对应产物就绪后运行；先执行独立套件。跨端证据绑定本轮生产者版本、合同/夹具版本及实际原始响应。失败报告中的场景仅在生产者版本、合同和场景证据完整性均可核验时可用；消费这些可用场景，缺失项记为阻塞；不能因报告缺一项让所有下游在收集阶段一起退出。

## 执行与收尾

本轮只运行和采集，不修改代码、断言、快照或规格。单项失败继续其他独立项；初始化失败阻塞依赖它的项，其他项继续。测试正常生成产物不算修改候选源码。发现外部编辑导致候选变化时记录受影响证据失效，重新固定后补验，不混合版本。

每个测试进程设置合理的外层超时，优先使用仓库既有预算，缺失时根据入口性质确定并记录。超时保存日志及可获取的线程栈，终止本轮拥有的挂起进程并继续独立项；不得无限等待。只有会破坏数据、污染共享环境或产生未授权副作用时，提前停止受影响部分并说明原因。构建、数据库、端口、生成物冲突的套件串行执行。

每项记录：范围及 AC/T 引用、命令、目录、版本与实际构建来源、起止时间、退出码、计数、原始日志、预期与实际、阻塞依赖。区分通过、断言失败、收集/编译失败、超时、跳过、未运行、阻塞和未知。零用例不算通过；日志未给出的数量保持未知；保留首次失败及后续复跑记录。

全部项结束或明确受阻才结束本轮。将失败按共同根因归组，区分实现、合同、测试装配、环境与尚未证实的线索；未经基线验证不把失败认定为历史问题。主线程分析各组影响范围、修复位置和验证方式，不能仅转述子代理猜测。
