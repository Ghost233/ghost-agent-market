# Ghost Matt Implement

平台差异：按用户要求，本版先在 Codex 试用并验证；Claude Code / ZCode 保留旧流程，验证后再同步，因此本技能暂仅发布于 Codex。

按规格和工单在当前分支、当前工作区完成开发与验收。本技能独立协调执行，不依赖其他技能的调度流程。进入完整验收前读取本技能的[整轮测试](references/testing.md)。

沿用项目已有规格、工单和进度位置；无约定时使用 `docs/specs/<主题>/spec.md`、该主题下的 `tickets/` 和 `progress.md`。工单通过稳定编号引用规格修订、合同和 AC 验收项。主线程维护进度中的当前阶段、规格修订、任务状态、文件写入归属、测试轮次与阻塞；状态区分待办、开发中、开发完成、验收通过和阻塞，不将开发完成当作验收通过。

主线程负责总任务与技术决定，常规 Git 操作直接完成。只有独立实现、测试执行或审查能产生有效并行工作时才委派。使用子代理时，调用 `collaboration.spawn_agent`，指定 `agent_type: "worker"`、`model: "gpt-5.6-terra"`、`reasoning_effort: "xhigh"`、`fork_turns: "none"`；宿主无法提供这些参数时说明限制，不静默换模型或声称已经委派。

派发任务提供职责、允许修改范围、规格/工单指针、依赖状态、完成条件、原始证据和升级条件。明确告知代理共享工作区还有其他工作，保留他人修改。普通进度稀疏通信，跨模块冲突和阻塞立即报告。

## 1. 接手并确认边界

读取规格、任务及已有进度，只推进用户授权范围。记录当前分支、各相关仓库 HEAD 与原有未提交/未跟踪改动；确认实际代码仍符合工单依赖。缺少任务时在已有明确规格内补最小任务清单；缺少关键设计时完成无关的安全部分，将受影响任务交回规格决策，不能让各代理猜测。

不新建分支、worktree 或临时集成目录替代当前工作区。主线程独占 Git 写操作与进度文档；子代理不切分支、提交、合并、stash、reset、清理或覆盖他人文件。用户已有改动保留并理解后接续；无法安全区分或会覆盖时报告具体冲突。

## 2. 当前工作区并行开发

主线程从依赖已满足的任务中分配不重叠文件/目录的写入归属。同一文件同一时间只有一个写入者；新增越界修改先报告，主线程在原写入者停止后移交或串行处理。共享类型、生成代码、依赖锁文件和配置由指定负责人处理，其消费者待必要检查通过后解锁。

子代理完成本任务实现与正式测试，做必要编译和定向验证；不自行启动全仓验收。共享数据库、构建输出、端口和代码生成会互相影响时由主线程串行安排。代理看到其他任务的半成品导致检查失败，应报告依赖状态，不越界修复。

主线程负责合同决策和阻塞处理。子代理返回改动文件、交付行为、定向结果与剩余问题；主线程核对依赖解除条件后再解锁下游，不能仅凭“已完成”消息判断。

完成条件：本批代码和正式测试齐备，所有代理停止写入，组合后的必要检查通过，剩余事项有明确状态。

### 跨模块与重复失败的升级

出现合同冲突、必须修改归属外文件、依赖假设失效，子代理停止相关修改，报告现象、证据、受影响模块及待决定事项。主线程暂停所有受影响的依赖任务，独立任务继续。

同一问题修复后仍复现、同类缺陷出现在第二个模块，或修好一处破坏另一处时，先停止试探性补丁，由主线程检查完整调用链、状态归属、依赖方向和资源生命周期。增加等待、重试、兼容分支不能代替诊断。

区分三种结果：实现偏离规格则修复实现；技术合同遗漏或矛盾则依据证据修订规格并同步工单；业务取舍或范围变化缺少授权时才向用户询问。整体诊断不预设必须重构，修复范围由根因决定。恢复前通知相关代理新的规格修订、合同和任务边界；受变更影响或影响尚不明的旧证据标为待验证；明确无关的证据保留。

## 3. 集中审查

对起始内容到当前候选的任务改动进行只读审查，覆盖项目规范、规格符合性、跨模块调用与资源生命周期。可委派独立审查，传完整变更范围和规格指针，不调用带 PR/worktree 前置条件的上游流程。收齐本轮发现后统一归因，按文件归属批量修复；有新变更或未决发现才复查相应范围。

完成条件：确定的开发/审查缺口已处理，候选可进入完整验收；不能称整体验收已通过。

## 4. 完整验收与批量修复

按整轮测试约定固定候选并派只读测试任务，独立套件继续运行，全部结束或明确阻塞后汇总。测试期间不修改候选代码；主线程可阅读和整理证据。

主线程按根因分组，区分实现、合同、测试和环境。独立组并行修复，跨模块组统一决定；涉及设计失效先更新规格与工单。修复期间仅做定向检查，本批完成后重跑整轮。用户只查询进度时回答后继续当前阶段，不重启执行。已授权修复持续推进，无需每轮等待用户再说“继续”；需业务决策或无法解决的外部阻塞则明确交付未完成状态。

## 5. 本地交付

核对全部任务、AC 验收证据及必测范围；跳过、未运行或环境阻塞不能冒充完成，已批准豁免单列。报告当前版本、通过范围、未解决事项和实际工作区状态，区分开发完成与验收通过。

提交和推送仅在已有授权内由主线程执行，显式选择本任务文件，不整体暂存混入其他工作。提交后确认交付内容与验收内容一致。推送后核对涉及本地分支与远端完整 hash；默认只做允许的 fast-forward，同步受未提交文件或分叉阻塞时保留现场并报告，不 stash/reset/rebase。无推送授权时本地交付即可，不虚构远端同步完成。此流程不创建 PR。
