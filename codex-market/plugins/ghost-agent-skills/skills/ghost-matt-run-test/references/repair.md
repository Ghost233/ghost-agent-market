# 已授权的批量修复

仅当用户本次或此前明确授权修复并继续测试时读取。运行和分析测试本身不授予修复、提交或推送权限。

在当前分支、当前工作区修复，保留用户原有修改。主线程负责根因判断与文件写入归属，同一文件同一时间只有一个写入者；子代理不切分支、创建 worktree、提交、stash、reset 或清理他人文件。Git 写操作只由主线程在已有授权内执行，不能将他人半成品整体暂存。代理参数沿用 SKILL.md。

本轮收齐后再开始修复。独立根因组可按文件归属并行，跨模块组统一协调。修复期间运行最小复现和受影响定向检查；本批修复全部完成、组合检查通过后，再固定新候选重跑完整验收范围。不要每修一个断言就重跑全套。

完整一轮的命令若已包含某个门禁，就复用该门禁的本轮证据。新改动、失败或未解决问题才构成额外复跑理由。规格、合同或范围变更按下方设计升级处理，不能降低断言、静默跳过必测项来换取全绿。


## 设计升级

出现合同冲突、必须修改归属外文件、依赖假设失效，子代理停止相关修改，报告现象、证据、受影响模块及待决定事项。主线程暂停所有受影响的依赖任务，独立任务继续。

同一问题修复后仍复现、同类缺陷出现在第二个模块，或修好一处破坏另一处时，先停止试探性补丁，由主线程检查完整调用链、状态归属、依赖方向和资源生命周期。增加等待、重试、兼容分支不能代替诊断。

区分三种结果：实现偏离规格则修复实现；技术合同遗漏或矛盾则依据证据修订规格并同步工单；业务取舍或范围变化缺少授权时才向用户询问。整体诊断不预设必须重构，修复范围由根因决定。恢复前通知相关代理新的规格修订、合同和任务边界；受变更影响或影响尚不明的旧证据标为待验证；明确无关的证据保留。
