# Ghost Matt Run Test

平台差异：按用户要求，本版先在 Codex 试用并验证；Claude Code / ZCode 保留旧流程，验证后再同步，因此本技能暂仅发布于 Codex。

单独执行用户指定测试范围，完整收集结果，由主线程分析。开始执行前读取本技能的[整轮测试](references/testing.md)。

沿用项目已有规格、工单、日志和测试入口；没有约定时可从 `docs/specs/<主题>/spec.md`、同主题的 `tickets/` 和 `progress.md` 查找证据，但缺少文档不阻止明确指定的测试。用现有 AC 验收编号和 T 工单编号记录关联，不为运行测试重建规划。

主线程确定范围、协调被测内容并判断原因，测试子代理只采集事实。使用子代理时，调用 `collaboration.spawn_agent`，指定 `agent_type: "worker"`、`model: "gpt-5.6-terra"`、`reasoning_effort: "xhigh"`、`fork_turns: "none"`；宿主无法提供这些参数时说明限制，不静默换模型或声称已经委派。

## 1. 确定范围

从请求、现有命令和上下文确定用例、文件、套件或全量范围，定位关联规格与工单；没有规格仍可运行明确指定的测试，将需求映射记为缺失。多个候选会实质改变范围时才询问，不把小范围请求扩大为全仓。

记录当前内容及实际构建来源，协调其他写入者暂停相关修改。根据入口依赖拆分可独立执行的批次，给测试子代理传准确范围、命令、版本、原始日志与边界。

若既有入口无法验证当前修改，交付明确阻塞及可选解决方式，不无限寻找替代入口；运行测试的授权不等于提交代码或修改 runner 的授权。

## 2. 执行一轮

测试子代理只运行和采集；按整轮约定处理首败、超时、依赖与计数，所有可执行项结束后返回。允许正常生成测试产物，不修改生产代码、断言、快照或规格。报告已有 runner 无法继续的缺口，不能声称未执行的项目通过。

除确认不稳定性或排除明确环境问题所需的有限复跑外，不重复启动同一轮；每次证据单独保留。需要未授权外部操作时返回具体阻塞。

## 3. 主线程分析

亲自对照期望、实际结果、规格和相关调用链，将全部失败按根因分组。检查模块职责、状态归属、接口合同、其他调用者和额外功能依据；没有架构问题证据时明确说明，不强行重构。

返回运行范围、版本、总体结论、完整失败/阻塞清单、关键日志，以及各根因组的证据、置信程度、最小修复建议与验证方式。没有依据的线索保持待确认，不能未经基线复测就称为历史故障。

默认到此结束，不自动修复或转入开发。若用户本次或此前已明确授权“修复并继续测试”，读取本技能的[已授权修复](references/repair.md)后继续，不能因本入口默认只测而再次要求相同授权。
