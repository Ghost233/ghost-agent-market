# MISSION.md 格式

`MISSION.md` 位于工作区根目录，记录用户学习该主题的_原因_。每一项教学决策——接下来教什么、推荐哪些资源、设计哪些练习——都必须追溯到此文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1–3 句话。描述用户追求的具体现实目标。掌握这项技能后，他们的生活或工作会发生什么变化？避免“理解 X”之类抽象表述，继续追问底层结果。}

## 成功的样子
- {用户将能够完成的一项具体、可观察的事情}
- {另一项具体事情}
- {…}

## 约束
- {时间、预算、既有承诺、学习偏好，以及任何限制方法选择的因素}

## 范围之外
- {用户明确暂时不想追求的相邻主题，用于保护最近发展区}
```

## 规则

- **每个工作区只有一个使命。** 用户要学习两个互不相关的主题时，应使用两个工作区。
- **具体优先于抽象。** “十月前跑完半程马拉松”优于“变得更健康”；“向团队交付一个 Rust CLI”优于“学习 Rust”。
- **拒绝模糊。** 如果用户说不清原因，先访谈再写文档。糟糕的使命比没有使命更糟。
- **现实变化时修订。** 使命会改变。用户目标转移时更新此文件，不要让过时使命继续指导未来会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而变成了计划。
