将本 skill 作为编写任何代理读取文档的参考，包括 skill、`AGENTS.md`/`CLAUDE.md`，以及通过指针触达的文档。它们的封装方式不同，写作原则相同：使用同一组杠杆让行为可预测，也就是让代理每次遵循相同的_过程_，而不是生成相同的结果。

编写 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由 skill。

## 上下文指针

**上下文指针**是代理上下文中的一条引用：它命名某份上下文外材料，并编码何时触达该材料。skill 的 description 是指针，`AGENTS.md` 中指向文档的一行也是同类对象。决定代理何时、以多高可靠性触达材料的是指针的_措辞_，而不是目标本身。必需材料若藏在措辞薄弱的指针后面，就是方差缺陷：先强化措辞，只有强化失败时才内联材料。

指针承担两项工作：说明材料是什么，并列出应触发它的**分支**。分支是文档处理的一种独立情形，不同运行会沿不同路径经过文档。始终加载的指针中，每个词都会在每轮产生成本，因此要比正文更严格地删减：

- **把引导词放在开头**：指针在这里完成触发工作。
- **每个分支只保留一个触发条件。** 为同一分支换用同义词只是重复书写；合并它们，只保留真正不同的分支。
- **删除正文已经承载的身份说明。**

## 两类负载

每增加一份文档或一个指针，都会消耗以下一种预算：

- **上下文负载**：始终加载的材料对代理上下文窗口造成的成本，例如 `AGENTS.md` 中的一行、skill description，以及每轮都占用 token 和注意力的任何内容，无论是否触发。
- **认知负载**：人类需要承担的成本，即记住有哪些文档、何时查阅。人类充当索引。这不是一味追求最小化的成本，而是人类自主性的代价；在人类判断重要之处投入，在不重要之处移除。

只能通过指针触达的材料免于正文上下文负载，但仍需支付指针那一行的成本；完全没有指针的材料则全部依赖认知负载。

## 信息层级

文档由两类内容构成：**步骤**（代理按顺序执行的动作）和**参考**（按需查询的定义、规则、事实）。两者可以自由组合：全是步骤（操作配方）、全是参考（审查规则、本 skill），或兼而有之。核心决策是每项内容在**信息层级**中的位置。该阶梯按代理需要材料的即时程度排序：

1. **文件内步骤**：首要层级，按顺序说明代理要做什么。
2. **文件内参考**：按需查阅。它常常是一组合理的扁平同级内容，例如同一层级上的全部审查规则；这种安排没有问题，不是坏味道。
3. **延迟披露的参考**：移到单独文件，通过上下文指针触达，仅在指针触发时加载。范围可以从同目录的相邻文件，一直到任何文档都能指向、位于任意位置的外部参考。

下移太少会让顶层臃肿；下移太多会隐藏代理真正需要的材料。整个决策就在于平衡这种张力。

**渐进披露**是沿阶梯下移：把内容移出主文件，放到指针后方，让顶层保持清晰。它首先不是 token 优化，而是保护信息层级的方法。分支是最清晰的判断标准：所有分支都需要的内容内联，只有部分分支会用到的内容放到指针后。文档包含步骤时，本应披露出去的文件内参考会淹没步骤，让代理是否关注步骤变成随机事件；这影响的是行为方差，不只是可读性。

**共置**是文件内的配套原则：层级决定内容_放多深_，共置决定它到达该层后_与什么放在一起_。把概念的定义、规则和注意事项放在同一标题下，不要分散，使代理阅读一部分时自然看到相邻内容。判断标准是文档应像专为代理编写的说明；成组材料符合，零散材料不符合。共置不同于去重：重复是在两处表达同一含义，分散则把一个含义拆碎到多处。

**蔓延**是这里的失败模式：即使每一行都有效且独特，文档仍然过长。注意力会被多余内容稀释，每增加一行都多一项需要保持相关性的负担。用层级解决：把参考资料披露到指针后，并按分支或顺序拆分，让每条路径只携带自身需要的内容。

## 步骤与完成标准

每个步骤都以一个**完成标准**结束，也就是告诉代理工作已经完成的条件。两项属性使它成为有效杠杆：

- **清晰度**：代理能否区分完成与未完成？“已经理解”之类模糊边界会诱发**过早完成**：步骤尚未真正完成，注意力却转向_结束工作_。后方可见的步骤——**完成后步骤**——产生拉力，标准的清晰度提供阻力。按顺序防守：先**收紧边界**，这是局部且低成本的；只有边界无法进一步明确、且确实观察到抢跑时，才通过拆分顺序隐藏后续步骤。隐藏必须跨越真实上下文边界（交接或派发子代理）才有效；内联调用不会清除上下文，后续步骤仍然可见。
- **要求强度**：标准要求做到什么程度。“覆盖每个修改过的模型”会强制彻底检查，而“生成变更列表”不会。要求强度驱动**跑腿工作**，即代理在任务内部进行的挖掘；它隐含在措辞中，无需单独写成步骤。它也不限于步骤：“应用每条规则”可以约束一组扁平参考，正如“完成每个步骤”约束一个序列，因此全参考型文档仍可设置完备性门槛。

最强的标准既可检查，又穷尽全部要求。

## 何时拆分

把一份文档拆成两份会增加某类负载，因此只有切口值得时才拆分：

- **按顺序拆分**：当完成后步骤诱使代理匆忙结束当前步骤时，拆开这段步骤序列。把后续步骤移出视野，会促使代理在当前任务中投入更多跑腿工作。反向操作要谨慎：合并序列会让每一步看到后续内容，诱发过早完成。
- **按调用方式拆分**：skill 特有，参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是模型预训练中已经存在、代理执行文档时用来思考的紧凑概念，例如_课程_、_战争迷雾_、_曳光弹_。把它作为 token 反复使用，而不是反复写成句子，会逐步形成分布式定义，并借用模型已有先验，以最少 token 锚定整片行为。清楚定义后也可以自造术语，但新词无法借用先验；预训练词免费提供的能力，自造词需要用定义 token 补足，因此优先寻找已有词。

它会锚定两次。正文中锚定_执行_：词每次出现，代理都会调用相同行为；在扁平参考中，它把注意力聚焦到一类目标。指针中锚定_调用_：当同一个词同时存在于提示、文档和代码库中，代理会把共享语言与材料相连，从而更可靠地触达。

主动寻找使用引导词重构的机会。在三处重复写出的三元组，或用整句话指向一个概念的指针，都应压缩成一个 token：

- “快速、确定、低开销” → _紧密_（_紧密_循环）。
- “你相信的循环” → _红色_：把模糊关卡变成可观察的二元状态（循环会因该缺陷变_红_，或不会）。

这样会获得双重收益：减少 token，并为代理提供更锋利的思考挂钩。假设每份文档都包含可被引导词淘汰的重复表述，主动找出它们。

**否定式指令**是这一杠杆旁的失败模式：用禁止来引导，会把被禁止行为带入上下文，使其_更_容易被想到。“不要想大象”之后，脑中只剩大象；否定词只是弱修饰，强激活概念会压过它，因此禁令有一半像是在要求执行该行为。使用**正向**提示，直接说明目标行为（“写单行注释”），不提被禁止行为。只有无法改写为正向表达的硬护栏才值得保留禁令；即使如此，也要配上正向目标，让注意力落在应做的事情上。

## 剪枝

- 每项含义只保留一个**单一事实来源**：放在唯一权威位置，使行为变更只需修改一处。**重复**是在多处表达同一含义，会浪费维护成本和 token，并让该含义在层级中的显著性超过真实等级。它与引导词恰好相反：引导词刻意重复 token，从不重复完整含义。
- **环境**也是事实来源，包括 `package.json` 脚本、配置文件、目录结构和 `--help` 输出。重述环境的文档是一个**缓存**：复制一次查询结果，只有查询本身昂贵时才值得承担负载。只缓存代理无法直接查明的内容：未成文约定、选择背后的原因、配置不会暴露的陷阱。单文件、单命令即可查询的事实留给环境，避免过时。
- 逐行检查**相关性**：它是否仍服务于文档目标？从未影响任务的纯说明、应延迟披露的分支，或因行为和现实变化而过时的内容都已失去相关性。短文档更容易维持相关性。没有剪枝纪律时，默认结局是**沉积**：因为添加看似安全、删除看似危险，过时层不断堆积，最终必须钻穿它们才能找到仍然有效的内容。
- 逐句寻找**空操作**：模型默认就会遵守的指令只增加负载，不改变行为。判断标准是“相较默认行为，它是否造成变化？”这取决于模型而非读者。两个人对空操作意见不同，本质是对默认行为判断不同，应通过运行文档而非争论来解决。句子未通过测试时，整句删除，不要只删几个词。该测试也适用于引导词：弱到无法改变默认行为的词（代理本来就大致认真时说“要全面”）是空操作；修复方式是换成更强的词（“不懈追查”），而不是换一套技巧。
