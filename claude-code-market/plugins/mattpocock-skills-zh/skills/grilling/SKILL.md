---
name: grilling
description: 围绕计划、决策或想法持续追问用户。适用于用户想对自己的思路做压力测试，或使用任何 “grill” 触发措辞时。
---

持续访谈用户，直到双方达成共同理解。把讨论绘制为一棵**设计树**：每个决策都分叉出依赖它的后续决策。

以**轮次**推进这棵树。**前沿**是所有前置条件均已确定的决策，也就是无需猜测尚未获得的答案、_现在_就能提出的问题。每一轮询问整个前沿：给问题编号，并为每个问题附上推荐答案。随后等待用户回答，再开始下一轮。

每个问题使用以下格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以有多个段落，也可以包含多个选项>

➡️ <你的推荐答案>
```

用户每轮的回答都会重塑设计树：已确定的决策会把前沿向外推进，并解锁依赖它们的问题。重新计算前沿，再提出下一轮问题。如果某个问题的答案依赖本轮仍未解决的另一个问题，就把它留到_后续_轮次，不要在本轮提出。

查明_事实_始终是你的工作，不是用户的工作。当前沿问题需要环境中的事实（文件系统、工具等）时，派出子代理调查；凡是可以自行查明的内容，都不要询问用户。不要为调查阻塞整个会话：正在进行的探索只是一个尚未确定的前置条件，因此只有依赖它的问题需要等待子代理报告，其余前沿问题现在就问。_决策_属于用户；逐一交给用户并等待回答。

当前沿为空时，会话才算结束：设计树的每个分支都已走过，没有留下任何未经说明的假设。在用户确认双方已经达成共同理解之前，不要据此采取行动。
