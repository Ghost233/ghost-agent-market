# 学习记录格式

学习记录保存在 `./learning-records/` 中，并使用连续编号：`0001-slug.md`、`0002-slug.md`，依此类推。仅在写入第一条记录时创建该目录。

它们相当于教学领域的 ADR：记录不显而易见的经验、关键洞见和用户声明的既有知识，以指导未来会话，并用于判断最近发展区。

## 模板

```md
# {所学到或确认内容的简短标题}

{1–3 句话：学到了什么（或确认了哪些既有知识），以及它为什么会影响未来会话。}
```

完整格式仅此而已。学习记录可以只有一个段落。价值在于记录_用户现在已经掌握什么_，以及_为什么这会改变下一步教学内容_，而不是填满固定章节。

## 可选章节

仅在确有价值时加入。大多数记录都不需要这些章节。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：先前理解被证明错误并遭替代时使用。
- **Evidence**：用户如何证明自己已经理解，例如答对问题、完成练习或说明既有经验。相关判断以后可能被重新审视时使用。
- **Implications**：这项理解为未来会话解锁或排除了什么。不显而易见时值得记录。

## 编号

扫描 `./learning-records/` 中的最大现有编号，并加一。

## 何时编写学习记录

满足以下任一条件时编写：

1. **用户真正理解了某项并不简单的内容**：不只是接触过，而是有证据表明他们能正确使用该概念。这会提高下一步教学的起点。
2. **用户说明了既有知识**：“我已经知道 X。”记录下来，避免未来会话重复教授，同时记录用户声称掌握的_深度_。
3. **纠正了误解**：用户先前持有错误认识，现在明白了原因。这类记录价值很高，因为它能预示相关主题中未来可能遇到的障碍。
4. **学习导致使命改变**：用户发现自己真正关心的内容与原先所想不同。链接到 [[MISSION.md]] 并更新它。

### 哪些情况_不_符合条件

- 仅仅讲过的材料。覆盖内容不等于学会；等待证据。
- 已在 [[GLOSSARY.md]] 中以术语定义简洁记录的内容。不要重复。
- 逐会话活动日志。学习记录不是日记，而是足以影响决策的洞见。

## 取代旧记录

后续记录与早期记录矛盾时（用户的理解加深或得到纠正），将旧记录标记为 `Status: superseded by LR-NNNN`，不要删除。理解如何演进的历史本身就是有用信号。
