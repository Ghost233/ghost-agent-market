当一个模糊想法大到单次代理会话无法容纳，而且从当前位置到**目标**的路线仍被迷雾遮蔽时，Wayfinder 用于寻找路线，而不是直接冲向目标。它在仓库的 issue tracker 上建立一张**共享地图**，再逐个处理**决策工单**：工单的产物是决定，不是待执行的构建切片。

每项工作的目标不同，绘图第一步就是命名目标；它会塑造每张工单。目标可以是待交接和迭代的规格、规划前必须锁定的决定，也可以是就地完成的数据结构迁移等改动。地图不限定领域。

## 规划，不执行

Wayfinder 默认只做规划：每张工单解决一个决定；当执行前不再有待决问题时，地图完成。想直接动手通常意味着已经到达地图边缘，应当交接。只有地图的 **Notes** 明确覆盖默认行为时，才把执行纳入地图。

## 始终按名称引用

地图和工单都是 issue，标题就是名称。在叙述和 “Decisions so far” 等所有给人阅读的内容中，使用带链接的名称，不要用裸 ID、编号或 slug。`#42, #43, #44` 难以阅读；ID 与 URL 应包在名称链接里。

## 地图

地图是当前仓库 issue tracker 上带 `wayfinder:map` 标签的单个 issue，也是规范产物；工单是它的子 issue。

地图是**索引**而非存储。决定只存在于对应工单中；地图只写一行摘要并链接，不重复详情。

地图、子工单、阻塞关系和 frontier 查询的具体表达取决于 tracker。应已提供 tracker 配置；否则运行 `/setup-matt-pocock-skills`。查阅 tracker 文档中的 “Wayfinding operations”。若仍未提供，默认使用本地 Markdown tracker。

### 地图正文

每次会话只需加载这份低分辨率全景。开放工单不写进正文，而是通过查询开放子 issue 获得。

```markdown
## Destination

<到达地图终点时的状态：规格、决定或改动。用一两行描述；每次选工单前先以此定向。>

## Notes

<领域；每次会话都应使用的 skill；本项工作的长期偏好>

## Decisions so far

<!-- 索引：每张已关闭工单一行，先给足够判断相关性的摘要，再通过链接查看详情 -->

- [<已关闭工单标题>](link) — <答案的一行摘要>

## Not yet specified

<!-- 战争迷雾：当前还无法制成工单的范围内问题；随着 frontier 推进而转为工单 -->

## Out of scope

<!-- 目标之外、明确排除且不会转为工单的工作 -->
```

### 工单

每张工单是地图的子 issue，以 tracker issue ID 标识，问题大小不得超过一次 100K token 会话：

```markdown
## Question

<本工单要解决的决定或调查>
```

每张工单带一个 `wayfinder:<type>` 标签：`research`、`prototype`、`grilling` 或 `task`（见[工单类型](#工单类型)）。

会话开始工作前，必须先把工单分配给驱动地图的开发者。assignee 就是占用声明；开放且未分配的工单才是无人占用。

阻塞必须优先使用 tracker 的原生依赖关系，让人能直接在 UI 中看见哪些工作可领取；仅当 tracker 不支持原生阻塞时，才退回正文约定。阻塞它的工单全部关闭后，该工单才算**无阻塞**。**frontier** 是开放、无阻塞且无人占用的子工单集合。

答案不写在工单正文，而在解决时记录（见[沿地图推进](#沿地图推进)）。原型等资产只链接，不粘贴进 issue。

## 工单类型

每张工单要么是 **HITL**（有人参与，由人代表自己发言），要么是 **AFK**（代理独立驱动）。HITL 只能通过实时交流解决，代理不得代替人回答。

- **Research（AFK）**：阅读文档、第三方 API 或知识库等本地资源之外的信息，找出某项决定所依赖的事实。由 `/research` **子代理**解决。
- **Prototype（HITL）**：制作便宜、粗糙、可供反馈的具体产物，如大纲、初稿、stub，或通过 `/prototype` 构建 UI/逻辑代码；适合关键问题是“应该长什么样/如何表现”时。
- **Grilling（HITL）**：默认类型，以对话推进；始终调用 `/grilling` 和 `/domain-modeling`。
- **Task（HITL 或 AFK）**：做出决定前必须完成的人工工作，例如注册服务、开通访问权、移动数据以观察形状。它只为解除决定阻塞而存在，不负责交付最终目标。代理能独立做就用 AFK，否则给人精确清单。完成后，答案记录所做工作以及后续工单依赖的凭据位置、URL、行数等事实。

## 战争迷雾

地图有意保持不完整，不要绘制当前看不清的内容。开放工单之外是**战争迷雾**：能预见将出现、但因仍依赖未决问题而无法精确定义的决定和调查。每解决一张工单，就清除前方一部分迷雾，把现在已经能准确描述的内容逐步转为新工单，直到通往目标的路线清晰。

地图的 **Not yet specified** 记录这片低分辨率视野：待调查的问题或以后要回看的区域。它们都在目标范围内，只是还不够清晰。也可供协作者了解工作方向。

判断标准不是“现在能否回答”，而是“现在能否准确陈述问题”：

- 问题已经清晰时建立**工单**，即使它被阻塞且暂时无法执行。
- 问题还无法准确表达时放入 **Not yet specified**。不要提前把迷雾切成工单大小；未来一片迷雾可能变成多张工单，也可能无需工单。

已经决定的内容、开放工单和范围外内容都不属于 **Not yet specified**。

## 范围外

迷雾只会聚集在通往目标的方向。目标决定范围；超出目标的工作属于 **Out of scope**，而不是迷雾。范围外工作不会转成工单；只有重画目标后，才能作为一项全新工作回来。

把内容排除在范围外是范围决定，不是路线上的一步。若现有工单后来被发现位于目标之外，应**关闭它**，并在 **Out of scope** 留下一行摘要、排除理由和已关闭工单链接。不要写入 **Decisions so far**，因为后者只记录实际走过的路线。

## 调用方式

有两种模式。除 research 工单外，**每次会话最多解决一张工单**。

### 绘制地图

用户以模糊想法调用时：

1. **命名目标**：运行 `/grilling` 和 `/domain-modeling`，明确地图通向的规格、决定或改动。目标先于其他内容确定范围。
2. **绘制 frontier**：再次追问，但采用**广度优先**，横向找出整个空间中的开放决定和现在可迈出的第一步。若完全没有迷雾，说明工作小到一次会话即可完成，不需要地图；停止并询问用户如何继续。
3. **创建地图**：添加 `wayfinder:map` 标签，填写 Destination 与 Notes，保持 Decisions so far 为空，并把迷雾写入 Not yet specified。
4. **创建当前能定义的工单**作为地图子 issue；所有工单拿到 ID 后，再在第二遍连接阻塞关系。不能定义的内容保留在迷雾中。
5. **启动 research 子代理**：为每张新 research 工单并行运行 `/research` 子代理，把结果放在一次性 `research/<name>` 分支，并从工单留下上下文指针。
6. 停止。绘图占用一次会话，不在同一会话人工解决工单。

### 沿地图推进

用户提供地图 URL 或编号时；工单参数可选，不提供就由代理选择下一项：

1. 加载地图的低分辨率全景，不要一次加载所有工单正文。
2. 用户指定工单则采用；否则按顺序选择第一张 frontier 工单。开始前先分配给自己以**占用**。
3. 解决工单。按需加载相关或已关闭工单详情，并调用 `## Notes` 指定的 skill；不确定时使用 `/grilling` 和 `/domain-modeling`。
4. 用**解决评论**记录答案，关闭 issue，并把上下文指针追加到地图的 Decisions so far。
5. 创建新发现的工单后再连接依赖；把因答案而变清晰的迷雾转成工单，并从 Not yet specified 删除对应内容。发现任一工单超出目标时，将其排除在范围外，而不是把它当路线决定解决。决定使其他地图内容失效时，应更新或删除相关工单。

用户可能并行处理多张无阻塞工单，因此必须预期其他会话会同时修改 tracker。
