# Ghos Matt Run Test

子代理执行测试并采集事实；主线程负责原因判断和修复方案。

## 主线程确定任务

1. 从用户请求和上下文定位指定测试的用例 ID、文件、套件或已有命令，以及对应 spec/ticket 与验收条件。目标仍有多个合理候选时先询问，不擅自运行全套测试。
2. 检查仓库现有测试入口与运行要求，使用已有配置。记录工作目录、提交和已知未提交改动；给子代理传目标、需求来源、准确命令或待解析的选择器、已有相关日志及运行边界。
3. 平台适配：Codex 使用 `collaboration.spawn_agent`，指定 `agent_type: "worker"`、`model: "gpt-5.6-terra"`、`reasoning_effort: "xhigh"`、`fork_turns: "none"`；Claude Code 使用 Agent 并指定 `model: "sonnet"`。两端工具和模型不同，其余流程一致。宿主不支持所需委派时报告阻塞，不冒充子代理执行。
4. 子代理不得修改业务代码、测试断言、需求或更新快照来制造通过；允许测试本身正常生成报告和临时产物。若运行需要未授权的外部写入、破坏性操作或超出指定范围的配置变更，返回具体阻塞。
5. 主线程等待子代理返回后亲自分析；不把子代理的猜测直接作为修复结论，不自动转入修复实施。

## 子代理执行与返回

确认命令选择器实际匹配指定目标，执行一次并保留输出；命令失败、发现零个测试、无法隔离目标或环境不满足时如实返回。只有为确认不稳定结果确有必要才做有限复跑，每次结果分别保留，不覆盖首次失败。

返回：
- 测试目标、spec/ticket 对应关系、实际命令、工作目录、提交及相关未提交改动。
- 开始/结束时间、退出码、执行/通过/失败/跳过数量；未报告的计数标未知。区分断言失败、测试未启动、收集失败、超时与未发现用例。
- 预期与实际行为、失败用例、关键堆栈和相关日志路径或原始输出片段；明确本次运行范围，不从局部通过推断整个项目通过。
- 已确认事实、待验证线索及环境阻塞分别说明。已通过也照实返回，不虚构修复需要。

## 主线程分析与方案

将测试期望、实际行为与 spec/ticket 原文逐项对照。必要时只读追踪失败路径、共享模块和其他调用者，取得足够证据后判断：

| 检查方向 | 必须回答的问题 |
| --- | --- |
| 实现缺陷 | 要求与断言合理时，哪条实现路径违背它们？根因在哪里？ |
| 测试或环境问题 | 断言、夹具、依赖服务、选择器、时序或环境是否导致失败？ |
| 架构问题 | 模块职责、状态归属、接口契约或依赖方向是否导致同类失败？局部补丁会否把问题留给其他调用者？ |
| 需求偏差 / 额外功能 | 断言或实现是否要求 spec/ticket 未规定的行为，或与明确的非目标冲突？有没有其他已批准需求、兼容性或安全约束作为依据？ |

不能仅因需求没写就判定功能多余，也不能为让测试通过而自动增加未批准的功能、放宽断言或删除测试。分别注明“需求明确要求”“其他约束有依据”“缺少依据/待确认”。架构检查可以得出“目前没有证据表明需要架构调整”，不强行重构。

最后由主线程给出：运行结论、证据支持的原因与置信程度、建议修复位置和最小变更、对其他调用者的影响、验证用例。确有架构问题时解释为何局部修复不足及必要的架构调整；属于额外功能或需求冲突时提出需求澄清或调整测试/实现的选项，不擅自扩展范围。证据不足时给出下一项最小诊断动作，不编造确定根因；通过且无其他问题时说明无需修复。
