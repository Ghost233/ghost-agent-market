# Ghos Matt Test Report

主线程负责确定范围与提供当前对话证据；子代理负责只读盘点并返回报告。

## 委派

1. 从用户指定内容、当前对话和仓库确定当前 spec 及全部关联 ticket。只在无法唯一确定范围时询问；缺失或不可访问的文档列为范围缺口，不能声称已全量覆盖。
2. 给一个子代理传入仓库绝对路径、spec/ticket 的路径或链接、当前分支与提交，以及刚才测试的命令、输出、时间和已知未提交改动。子代理不能看到父线程历史时，必须直接传递相关原始结果；没有结果就明确说明缺失。
3. 平台适配：Codex 使用 `collaboration.spawn_agent`，指定 `agent_type: "worker"`、`model: "gpt-5.6-terra"`、`reasoning_effort: "xhigh"`、`fork_turns: "none"`；Claude Code 使用 Agent 并指定 `model: "sonnet"`；ZCode 使用 Agent 调用本插件 `zcode-agents/` 中的 `ghost-agent-skills:ghos-matt-test-report` 子代理，其配置固定为 `model: glm-5.3-flash`。ZCode 专用目录由 `.zcode-plugin/plugin.json` 的 `agents` 声明，仅 ZCode 加载；各平台工具和模型不同，其余流程一致。宿主不支持所需委派时报告阻塞，不冒充子代理执行。
4. 子代理只读取文档、现有测试、报告和日志，不运行测试、不修改文件。主线程等待返回，核对统计口径后展示报告。

## 子代理盘点规则

- 逐一提取 spec/ticket 中的测试场景、验收条件、边界和异常路径，包括尚未实现的测试；保留来源定位。重复项合并并保留全部引用，不把文档未指定的想象场景加入必测清单。
- 将要求映射到实际用例、测试套件或人工验收证据。按 spec → ticket → 测试层级分组（单元、集成、端到端、人工等）；spec 级公共要求单列，跨 ticket 共用测试不在总计中重复。
- 优先使用刚才的运行结果，再补充最近已有结果。每个结果记录命令/用例、时间、代码版本与日志出处；信息缺失就标未知。旧提交结果、相关代码运行后有变化或无法确认对应版本的结果标为历史/待验证，不计入当前已通过。
- 明确区分：通过、失败、跳过、未运行、阻塞、未知、历史/待验证，以及要求缺少对应测试。退出码为零但未发现任何测试不能算通过；套件摘要不能推断未列出的单项结果。
- 仓库已有但无法映射到当前 spec/ticket 的测试可单独列为“未关联测试”，不自动视为额外功能，也不混入需求覆盖率。

## 返回格式

报告先注明范围和证据时间，再按组展示：

| Spec / Ticket | 测试层级 | 测试内容 / 用例 | 需求来源 | 最近结果与当前状态 | 运行证据 |
| --- | --- | --- | --- | --- | --- |

条目多时，每组用 `N/M` 汇总；N 是当前代码有证据通过的唯一测试数，M 是该组已识别的全部唯一测试数，包含未实现、未运行、跳过和阻塞项。M=0 写“无已识别测试”，不显示通过率。单独展示所有失败、覆盖缺口、阻塞和待验证项，并给出其余明细的来源或本次返回的可展开明细，不能静默丢项。

区分“验收项覆盖 N/M”和“实际用例通过 N/M”：一个验收项可能对应多个用例，不能混加。只有取得完整用例清单时才能给精确用例分母；仅有 runner 摘要时按原口径标为“该次运行通过 N/M”，不能冒充需求覆盖或当前整体通过率。

“已有测试覆盖 N/M”的 N 是已完整映射到可执行测试或明确人工验收步骤的验收项数，不代表通过；“当前验收通过 N/M”的 N 是所有对应检查都有当前通过证据的验收项数。两者的 M 均为去重后的全部验收项数；只覆盖部分条件不能把整项计入 N。
