# 新 skill 提案与贡献

本仓库不接受新 skills 的提案或贡献，包括附有现成分支或 fork 的提案。

## 不属于维护范围的原因

目录只收录我日常亲自使用的 skills，并刻意保持小规模。每个 skill 都会永久增加维护工作：它必须与其他 skills、文档页面、`ask-matt` 的路由表，以及插件清单同步。Skills 越少越短，保持正确的成本就越低。

我对自己的想法采用的规则也适用于这里：现有 skills 能组合出某种行为，就不新增 skill。多数提案是由 grilling、`to-spec`、`to-tickets`、`implement` 等组成的特定工作流。这种组合应写进你自己的提示或 skills。

欢迎自行发布 skill。skills.sh 让这件事很直接，本仓库无需知道它。

这个规则只针对**新** skills。已有 skill 的具体失败，和其他 issue 一样，按 [`SCOPE.md`](../SCOPE.md) 的标准判断。
