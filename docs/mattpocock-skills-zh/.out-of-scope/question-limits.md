# Grilling 提问数量的硬限制

`/grill-me` skill，以及其他 skills 中的 grilling 会话，不设置最大问题数。要求增加可配置上限或硬限制，不属于维护范围。

## 不属于维护范围的原因

Grilling 刻意保持开放。目标是持续挖掘，直到决策树的每个分支都解决。有的计划需要三个问题，有的需要五十个。固定上限会提前终止复杂问题的有效探索，也会在简单问题中显得随意。

会话太长时，现有退出方式已足够：

- 用户随时可以结束会话，接受计划的当前状态。
- 用户可以让模型收尾、总结并继续下一步。自然语言引导就是预期的控制方式，无需数字限制。

硬限制也会混淆两类失败：模型因为计划确实描述不足而提很多问题，属于按设计工作；模型提出重复或低价值问题，属于提示质量问题，而非数量问题。后者应在 skill 提示中修复，不靠计数器。
