## 它做什么

`grill-me` 从一个**模糊想法**开始追问，直到你能够承诺采用它。开始前无需准备完整计划，因为[会话](https://www.aihero.dev/ai-coding-dictionary/session)就是为了形成计划。提问按**轮次**展开。每轮覆盖整个**前沿**，即所有前置条件已经确定的问题。它不会问你依赖尚未收到答案的问题。

它是**[无状态的](https://www.aihero.dev/ai-coding-dictionary/stateless)**。它不写文件，也不留下工作区。唯一结果是你头脑中的想法更清楚。

## 何时使用

输入 `/grill-me` 调用它；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行使用。在**新对话**中开始，而非接着代理已经写好的计划继续。

只要有值得认真考虑的想法就可以使用，例如功能、产品方向、业务决定或文章。无需先弄清具体涉及什么。会话就是为了解决模糊之处，所以想法模糊不是等待的理由。如果已经能够精确定义，就不需要深入追问。

三个追问 skills 的选择，取决于你面对的情形：

- **任何地点的任何主题。** 使用 `grill-me`。它不需要仓库，不写文件，主题也无需与代码有关。
- **需要结合代码库。** 使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)。它运行相同访谈，但[保存状态](https://www.aihero.dev/ai-coding-dictionary/stateful)：读取代码，把所得内容保存在 `GLOSSARY.md` 和 ADRs 中。
- **单次会话容纳不下。** 使用 [wayfinder](https://aihero.dev/skills-wayfinder)。它把工作绘制成地图，在地图中运行追问会话。

关闭[计划模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。计划模式会让代理急于产出计划，而这里需要它持续提问。

## 对话中的主动参与

Skill 负责提问，但**你**掌握范围。人们经常忽略这一点。它决定会话能否把想法变成决策，还是产出看似自信的胡话。

失败方式是**被动回答**：对 40 个问题不断说“同意”，最后得到一份由代理写出、你逐项点头的计划。长会话让人感觉很有产出，但你没有作出决定，结果却显得过于确定。

主动参与意味着引导对话。问题不够详细时提出异议；范围偏移时说出来；不知道时明确说“我不知道”。这个 skill 帮助工程师，但不能替代工程师。结果质量取决于答案质量，而非问题数量。

相反的错误确实存在，但较少见：访谈持续太久，始终没有开始写代码。

## 能靠追问解决与不能靠追问解决的问题

有些问题可以通过谈话回答。有些不行，追问再多也解决不了。

“一张长表单还是三个页面？”和“这个交互应该是什么感觉？”属于**不能靠追问解决**的问题。需要先看到可供回应的东西，才能回答。遇到这种问题时停止追问，用 [prototype](https://aihero.dev/skills-prototype) 构建一次性版本，看过后再回来用一句话回答。

试图通过谈话解决这种问题，会让会话变得太长。代理不断换一种说法，你不断猜测，范围也随着不确定性扩大。

## 有效运行的表现

- 你会对某些内容提出异议。如果全程没有异议，可能本来就不需要这次会话。
- 问题分成少数几轮，后续轮次明显基于之前的回答，而非长期一次只问一个问题。
- 结果与你最初预想不同，因为某个问题揭示了你没意识到自己正在作出的决定。
- 结束时，你能够向未参与会话的人解释每项选择的理由。

## 常见问题

**会问多少个问题？怎么知道何时结束？**
看轮数，不看问题数。四轮共 46 个问题很常见。前沿清空时结束：每个分支都已访问，没有未说明的假设。

**它问了 200 个问题，哪里出错了？**
通常是范围太大。先让代理把工作拆成小块，再逐块追问。很长的会话也会进入**[迟钝区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**：[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)已经足够满，问题质量开始下降。

**可以恢复成一次一个问题吗？**
可以。在全局 `CLAUDE.md` 中加入：

```
深入追问时，一次只问一个问题。
```

**我确实不知道答案怎么办？**
直接说。“我不知道”是有效答案。无法回答的问题，通常意味着应该做原型，而非猜测。

**写 spec 前要另开一次会话吗？**
不需要。这次会话的价值就是刚建立的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。把同一段对话直接交给 [to-spec](https://aihero.dev/skills-to-spec)。

**模型有影响吗？**
比多数 skills 更大。深入追问依赖[模型](https://www.aihero.dev/ai-coding-dictionary/model)本身对系统如何失败的知识，因此使用你最好的模型。实施主要遵循上下文，那里使用便宜模型也可以。

## 在流程中的位置

`grill-me` 是一个**可在任何地点、针对任何主题独立运行的工具**。它无状态，因此便于迁移，不需要仓库、工作区或配置，也不假定主题是软件。人们用它思考业务决定、写作和下一步行动：任何自己无法独自想清楚的事。

与 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的区别只有这种可迁移性。后者运行相同访谈，同时读取代码库，并把所得内容记录为 `GLOSSARY.md` 和 ADRs。两者底层都使用 [grilling](https://aihero.dev/skills-grilling)。`grill-me` 是不保存状态的用户调用入口。

如果追问的主题最终确实是软件，可以把同一段对话交给 [to-spec](https://aihero.dev/skills-to-spec)，继续进入构建流程。这是可选后续路径，不是这个 skill 的目的。不确定适合哪个流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会帮你选择。
