## 它做什么

`writing-for-agents` 是编写代理文档的参考，包含 skill、`AGENTS.md`、`CLAUDE.md`、[spec](https://www.aihero.dev/ai-coding-dictionary/spec)、运行时提示词、README，以及[代理](https://www.aihero.dev/ai-coding-dictionary/agent)读取的任何文档。格式虽然不同，写作方法相同。同一组杠杆使行为可预测，让代理每次运行遵循同一*过程*，输出则未必相同。

默认修复是删除多余内容。要求代理为另一个代理写指令时，它的大部分文字会解释[模型](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的内容。这些行都是**空操作**：消耗[上下文](https://www.aihero.dev/ai-coding-dictionary/context)，却不改变行为。本参考帮助找到它们，因此对现有文档与空白文件同样有用。

在 v1.1 之前，它叫 `writing-great-skills`。新名称更符合它一直以来的作用，几乎没有内容只适用于 skills。Skill 专属机制，包括 frontmatter、模型调用与用户调用的选择、路由 skills，放在链接的 `SKILL-MECHANICS.md` 中，只有面对 skill 文档时才读取。

## 何时使用

输入 `/writing-for-agents`，或在创建、编辑 skill，修改 `AGENTS.md`、`CLAUDE.md` 时，由代理自行使用。

其他代理读取的内容需要你手动调用，包括文档、specs、[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)、系统提示词与 [AFK](https://www.aihero.dev/ai-coding-dictionary/afk) 提示词。判断只有一个问题：代理会读它吗？代理通过指针、人类粘贴，还是仓库文件得到文档，都不影响判断。想查明代码库内容，用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)。本参考负责文档如何表达，而非文档知道什么。

## 两类负载

核心概念是每份文档和每个指针消耗的两种预算：

- **上下文负载**：始终加载的材料对代理窗口造成的成本，例如 `AGENTS.md` 一行、skill description，以及不论是否触发、每[轮](https://www.aihero.dev/ai-coding-dictionary/turn)都位于上下文的内容。
- **认知负载**：你记住有哪些文档、何时查阅各文档的成本。你充当索引。不应一味最小化这个成本，因为它是人类自主性的代价。

从两类负载考虑，多数写作决策，例如是否拆分、内联或延迟披露、指向或直接提供，都是在不同位置作同一种权衡。

## 可用的杠杆

- **[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)**：上下文中的引用，命名上下文外材料，并说明何时触达。Skill description 与 `AGENTS.md` 中指向文档的一行是同类对象。代理能否可靠地跟随指针，取决于指针的*措辞*。
- **信息层级**：从文件内步骤，到文件内参考，再到指针后的延迟参考。**[渐进披露](https://www.aihero.dev/ai-coding-dictionary/progressive-disclosure)**是把材料沿层级下移，保持顶层易读。
- **完成标准**：每步完成条件的清晰度和要求强度，以及要求带来的**跑腿工作**。它们防止**过早完成**。
- **引导词**：模型预训练中已有的紧凑概念，例如*紧密*、*红色*、*曳光弹*，代理运行文档时用它们思考。正文中引导执行，指针中触发调用。
- **剪枝**：逐句应用单一事实来源、相关性与空操作测试，清除**重复**、**沉积**和**蔓延**。

## 常见问题

**`/writing-great-skills` 去哪了？**
就是这个 skill，在 v1.1 重命名。改名前很久，用户就用它处理 `AGENTS.md`、文档、specs、工单和运行时提示词。结构、引导词与剪枝适用于代理读取的任何文本。没有别名，请用新名称重新安装。

**“为代理写作”是让代理来写吗？**
作者是你，读者是代理，这就是困难所在。读者已经读过一切，因此额外解释没有价值，精确表达才是任务。

**直接让代理代写可以吗？**
可以，但通常会得到啰嗦文本。模型自行写作时会解释已知内容，不会主动执行空操作测试或寻找引导词。用这个参考审查草稿，多数价值来自这轮审查。

**我让代理精简文档，它把功能删了。**
代理收到“精简”要求后，会优化长度，因为长度可见。空操作测试检查行为：删除一行，判断代理行为是否改变。句子没通过测试时，删整句；存在争议时，通过运行文档解决。

**怎么知道完成了？**
文档有效运行，且再也找不到重复、沉积或空操作时完成。没有自动评估。手动运行文档，用失败方式词汇诊断问题。文档行为异常时，同一套词汇也能帮助修复：先命名失败方式，再修复。

**应该放在 `CLAUDE.md`，还是其他地方？**
判断愿意支付哪类负载。`CLAUDE.md` 无条件加载进每次[会话](https://www.aihero.dev/ai-coding-dictionary/session)。指针后的材料在触发前只消耗指针那一行。十次会话中只有一次适用的内容，在其他九次都会消耗上下文负载。

**每换新模型都要重写文档吗？**
多数时候不用。过度适配单一模型也会带来问题。为新模型更新，通常只需再检查一遍空操作。

**Skill 只对创建它时的那个具体任务有效。**
常见方法是先做一次工作，再让代理写成 skill。这容易过度拟合那次运行，示例也过于具体。保留原运行作为证据，再有意泛化：去掉属于特定仓库和文件的细节，面向整类任务写作。

**英语不是母语，会失去引导词优势吗？**
不会。寻找以最少 [tokens](https://www.aihero.dev/ai-coding-dictionary/token) 承载最多行为的词，正是这个参考帮助完成的工作。

## 有效运行的表现

- 文档随着质量提高而变短，剩余内容之少会让你意外。
- 指出一个引导词，可以看到它在不止一处改变代理行为。
- 没有内容以任何形式重复说明。重复是文档从未测试过的最可靠迹象。
- 只有一个分支需要的参考，放在指针后，而非主文件中。

## 在流程中的位置

这是随时可用的独立参考，适用于整套内容。这里的每个 skill 都用它编写；其他 skills 生成的 `GLOSSARY.md`、ADRs、spec 和工单，一旦要交给代理读取，也适用。唯一直接调用它的是 [retro](https://aihero.dev/skills-retro)，该 skill 在提出任何引导文件或 skill 前加载它。不确定哪个 skill 或流程适合任务时，[ask-matt](https://aihero.dev/skills-ask-matt) 会帮你选择。
