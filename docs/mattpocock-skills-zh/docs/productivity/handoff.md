## 它做什么

`handoff` 把当前对话压缩为一份**交接文档**：一个 Markdown 文件，写入操作系统临时目录，供新的[代理](https://www.aihero.dev/ai-coding-dictionary/agent)读取并接续工作，不写进工作区。

它提供的是**可迁移性**，所以适用范围比名称听起来更窄。只有工作需要*转移*时才需要文件：转到新[代理运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)、新目录、同事，或要分出去的旁支任务。没有内容需要转移，就无需交接。留在当前[会话](https://www.aihero.dev/ai-coding-dictionary/session)、`/clear`、[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)和 `/compact` 足以处理普通的阶段结束情形，`/compact` 的使用机会通常更多。

## 何时使用

输入 `/handoff` 调用，代理不会自行使用。附上下一次会话的目的，skill 就会针对这个目的写文档。

触发情形只有四种：

| 情形 | 为什么需要文件 |
| --- | --- |
| 更换代理运行环境（Claude → Codex） | 新运行环境看不到原来的[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 转到其他目录或仓库 | 常见情况是转到原型目录 |
| 把工作交给同事 | 对方需要可读材料 |
| 在阶段中途分出旁支任务 | 你继续工作，另一个代理接手分支 |

其他情形，例如运行环境与目录不变，完成[深入追问](https://www.aihero.dev/ai-coding-dictionary/grilling)后转入实施，使用 `/compact`。[ask-matt](https://aihero.dev/skills-ask-matt) 提供阶段边界上五种选项的有序决策树。

## 容易忽略的分支用途

Skill 的 description 看起来像会话恢复：写摘要，在这里结束，在那里继续。这样理解会让它显得不如 `/compact`，所以人们跳过它。值得了解的是分支情形：你**留在当前会话中**，把积累的上下文副本交给第二个代理，并行工作。

[prototype](https://aihero.dev/skills-prototype) 的临时探索会用到这种做法。设计对话进行到一半，碰到只有运行代码才能确定的问题，又不想用已经建立的主对话去探查。交接给原型会话，得到答案，把答案交回来，并从原对话引用它。工作跨越两次，原对话一直保留，你无需重新解释。

阶段边界上的五种选项中，有三种保留不同的东西：`/compact` 保留意图，`/clear` 清空内容，`/handoff` 保留工作的可迁移性。

## 文档承载什么

文档承载当前工作线索：在做什么、为什么、下一步是什么；还有一个**建议使用的 skills**章节，说明下一个代理应使用什么。Skill 写文件前会脱敏秘密。

文档有意排除已经记录的内容。Specs、计划、ADRs、issues、提交和 diffs 只通过路径或 URL 引用，从不复制。这让文件保持小，也让已经确定的细节留在一个位置，避免两个副本各自变化。

## 常见问题

**该用交接还是压缩？**
只有内容需要转移时才交接，其他情况用 `/compact`。继续同一任务通常属于压缩。运行环境和目录都不变，并且需要你继续参与时，阶段边界决策树多数时候落在 `/compact`。`/handoff` 的优势是结果为文件，可以带到 `/compact` 无法触及的位置。

**compact、clear 和 handoff 的具体区别是什么？**
各自保留不同内容。`/compact` 压缩上下文，在新窗口继续，使意图保留下来。`/clear` 清空窗口，从头开始；之前所有内容都可以丢弃时适用，否则无法撤销。`/handoff` 写出可迁移文件，让工作能转到别处继续。三者都把**[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（实际发生的对话）变成**[二手来源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（对话摘要）。只有继续当前对话不做这种转换，因此先排除继续选项。

**交接文件在哪里？**
临时目录。这是关于 skill 最常报告的问题。它优先使用 `$TMPDIR`，否则 `/tmp`，Windows 上使用 `%TEMP%`，但路径很长。离开前让代理返回路径，并保存它。临时目录是有意的选择，因为交接文档正在转移，而非需要维护的产物。临时目录也不持久，见下一问。

**交接文件在两次会话之间消失了。**
一些环境会在会话之间清空临时目录，报告案例是 Codex；重启也会清空 `/private/tmp`。下一次会话如果不会在一小时内启动，或将使用不同运行环境，写出后立即自行复制到持久位置。文档*指向*的文件同样如此：派发说明引用其他临时文件时，下一个代理也无法读取它们。

**怎么交给下一个代理？**
打开新会话，指向文件路径，让它读取后继续。指向文件，不把摘要插入 Shell 命令。把含反引号或 `$(...)` 的摘要插进 `claude "<summary>"`，Shell 会破坏内容。通常是无提示截断，而非报错，于是新代理拿着不完整说明开始，且没有提示。

**它与 `/branch`、`--fork-session` 或内置 `/handoff` 一样吗？**
相似，但不同。这里没有发布 `/branch` skill，标准名称是 `/handoff`。Fork 继承上下文的精确副本；这个 skill 针对明确的下一任务，生成文件形式的定向压缩。同机器、同运行环境、同目录下可以 fork 时，fork 更省事。目的地无法通过 fork 到达时，文件更合适。

**什么内容应该放进 `CLAUDE.md`？**
判断它到下个月是否仍然成立。`CLAUDE.md` 是项目的长期上下文，无论相关与否，每次会话都会加载。交接文档围绕一项进行中的工作，工作完成后就失去用途。反复解释的事实应放进 `CLAUDE.md`，完成到一半的任务应放进交接文档。

**它记录了做什么，却没记录为什么。**
这是合理的批评，也经常有人提出。两点有帮助：传入参数，告诉它下一次会话的目的，让它保留与那个目的相关的推理。还要检查本次会话未验证过的自信断言，例如“X 还没做”或“Y 已完成”。下一个代理会信任文档，不重新检查。把推测写成事实，会成为后续一切工作的错误前提。交接前阅读文档，把只是假设的内容降为假设。

**为什么做成 skill，而不是斜杠命令？**
两种方式都能工作，适合不同情形。作为 skill，它和这里其他内容使用相同安装与更新路径，便于共享。禁止代理自行触发的是 frontmatter，而非机制。

## 有效运行的表现

- 文档长度仅占对话的一小部分；specs、issues 和 diffs 通过路径与 URL 出现，而非复制文本。
- 不打开原会话，直接阅读也能知道下一步做什么。
- 新代理直接开始工作，无需让你重新解释配置。
- 分支情形中，你返回原会话时，原会话保持原样。
- 建议 skills 章节列出了你自己也会选用的 skill。
- 文档不包含密钥、token 或密码。

## 在流程中的位置

`handoff` 是一个**随时可用的独立工具**。它在会话之间工作，范围较窄，使用次数通常少于阶段边界上的其他四个选项。最接近的工具是 [prototype](https://aihero.dev/skills-prototype)，因为原型位于独立目录，来回交接正是这个 skill 的用途。到达边界，不确定该继续、清空、交接、委派还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 提供按顺序判断五种选项的决策树，也会引导你使用其他 skills。
