## 它做什么

`teach` 把运行它的目录变成长期开设课程的工作区，在多次[会话](https://www.aihero.dev/ai-coding-dictionary/session)中教你一个主题，使用简短、自包含的 HTML 课程。

它不直接依靠[模型](https://www.aihero.dev/ai-coding-dictionary/model)已有知识教学，而把[参数知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)视为不可信。教学前先查找高可信资料，记录到 `RESOURCES.md`，并在每节课中引用。它还[保存状态](https://www.aihero.dev/ai-coding-dictionary/stateful)：学习目的、资料、课程和已掌握内容的记录，都作为目录中的文件保存。下一次会话从文件继续，不依赖上次对话剩余的内容。

## 何时使用

输入 `/teach` 调用，[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行使用。

学习本身就是项目时使用，例如语言、框架、新加入的代码库、瑜伽、着色器或认证。它不适合顺便解释一件事。

| 你的目标 | 使用 |
| --- | --- |
| 花数周学习一个主题，多次会话持续积累 | `teach` |
| 在当前会话中解释一个概念 | 在该会话中直接问 |
| 代理上一条消息没听懂，需要重新解释 | [wait-what](https://aihero.dev/skills-wait-what) |
| 打磨已有思考，而非获取新知识 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让后台代理阅读[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)，留下带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学习追问中途出现的内容，又不打断[追问](https://www.aihero.dev/ai-coding-dictionary/grilling) | 用 [handoff](https://aihero.dev/skills-handoff) 交接到教学工作区，再在那里运行 `teach` |

## 前提条件

`teach` 构建一个目录，默认每个工作区只有一个学习目的，所以在你愿意专门用于单一主题的地方运行。与正在工作的项目分开。独立仓库是最好的位置，优于全局 `~/.learnings/` 或当前项目。专用仓库也能让你提交课程，团队就是通过这种方式共享。

目录中会积累：

| 路径 | 内容 |
| --- | --- |
| `MISSION.md` | 为什么学习这个主题。其他文件都依赖它。缺失时，`teach` 首先访谈你，直到目的明确 |
| `RESOURCES.md` | 经过核对的教学来源，分为 Knowledge（知识）和 Wisdom（社区经验） |
| `lessons/*.html` | 编号课程，教学的主要单元 |
| `reference/*.html` | 精简速查表、算法、术语表等会反复查阅的文档 |
| `learning-records/*.md` | ADR 风格的笔记，记录已证明掌握的内容，用于决定下一课 |
| `assets/*` | 可复用组件，从共享样式表开始，让课程看起来属于同一系列 |
| `NOTES.md` | 你说明的教学偏好 |

关于这个列表有两点说明。多数主题适合术语表，但 skill 自带的 `GLOSSARY-FORMAT.md` 已不再被 `SKILL.md` 链接，所以只有你主动要求时才会创建（[issue #559](https://github.com/mattpocock/skills/issues/559)）。所有文件都写入运行 `/teach` 的目录。

## 记忆强度

关键概念是**记忆强度**：长期保留能力。它区别于**流畅感**，即阅读时看似掌握、但一周后就消失的即时回忆。`teach` 通过合意难度建立长期记忆，包括提取练习、间隔和交错练习。先获取知识；这个阶段困难会占用理解所需的工作记忆，反而妨碍学习。之后 `teach` 用紧密反馈循环练习技能，困难才成为有效工具。

两件事决定教学内容。**学习目的**是你学习这个主题的具体现实原因，是每节课的基础。缺少目的，课程会变抽象，也无法决定下一步。`teach` 根据目的和学习记录，在你的**最近发展区**内选下一课：难到需要努力，但又没有超前到无法学会。

记忆强度也解释了为什么 skill 会提出异议，而非一味同意。需要**经验判断**的问题，先尝试回答，再推荐能检验答案的社区。Skill 不会让你跳过测验。有用户说“非常感谢”后，被告知练习还没完成。

## 课程、参考资料与组件

一节**课程**是一个自包含 HTML 文件，短到可以一次学完，围绕学习目的，让你获得一项具体能力。它引用来源，推荐一个值得亲自阅读的一手来源，并链接到其他课程和参考文档。

你很少回看课程，但会回看参考文档。因此，课程的精简形式，例如语法表、算法、姿势序列、术语表，应该放进 `reference/`，而非埋在首次介绍它的课程中。

课程用 `assets/` 中的**组件**构建，包括样式表、测验控件、模拟器和图表辅助工具。默认复用。代理编写课程前先读取 `assets/`，从已有内容构建。新增内容如果第二节课也能使用，就写成组件。共享样式表是每个工作区的首个组件，让页面看起来像同一课程系列。

## 常见问题

**文件写到哪里？我的文件出现在 `~/.claude/skills` 中。**
写到运行 `/teach` 的目录（[#377](https://github.com/mattpocock/skills/issues/377)）。

**一直用同一会话，还是每节课新开会话？**
三种方式都可以：留在同一会话、新会话重新调用 `/teach`，或在同一目录打开新会话。每节课都是一次独立调用。课程状态在目录中，不在对话中。常见做法是在工作区开新会话，说 `/teach next lesson for <topic>`。

**怎么知道它不是编造知识？**
不能仅凭 skill 的保证判断。需要阅读一手来源。`teach` 和任何基于 LLM 的 skill，都不足以让你不经检查就信任。`RESOURCES.md`、每课引用和每课推荐的一手来源，使核对成本更低，但仍需核对。这类失败已经发生：有用户学习二阶魔方时，收到不能解出魔方的虚构转动序列。遇到这种情况，检查模型、代理运行环境、推理投入设置和来源。风险最高的是使用精确记号的操作性领域，最低的是可立即验证的输出，例如能运行的代码。

**测验正确答案总是第一项。**
多人在 Sonnet、Opus 和 GLM 上确认了这一问题，仍未修复。`SKILL.md` 现在要求每个答案字数相同，消除了另一条线索：以前正确答案常是唯一完整解释的选项。但这没处理位置问题。一名贡献者测试了指令层修复，九节课中的 33 个答案仍全部落在 A 项（[#335](https://github.com/mattpocock/skills/issues/335)）。因此，真正的修复是 `assets/` 中打乱答案顺序的测验组件。它发布前，忽略答案位置。你可以修改自己的 `assets/`，要求增加渲染时随机排序的组件，作为本地修复。

**它假定我已经知道某些内容，使用术语却不定义。**
这是最常见的实际抱怨。Skill 没有评估步骤，它从学习目的和学习记录推断你的水平，而第一次会话没有学习记录。一名在 wayfinder 流程中运行它的用户直言：“它从未追问我的起点，所以对我已经知道的内容作了很多假设。”另有人报告课程使用未定义术语；有关硬件的课程只说能做什么，却没说不能做什么。两点有帮助：首条消息说明已有知识和缺口；课程水平不合适时明确纠正。纠正会成为学习记录，影响下一课。显式知识评估仍是功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），尚未发布。

**它支持间隔重复吗？知道何时停止教学吗？**
前者不支持，后者不可靠。课程设计考虑间隔和交错，但没有任何机制安排复习，也不集成 Anki 或日历，用户经常要求这些能力。另一个缺口是退出标准。一位用户说，`teach`“很擅长做下一课，却不太会判断什么时候停下来，转入复习或实际练习”。希望复习或练习时，请明确要求，它不会自行建议切换。

**只适合代码吗？**
不是。报告中的多数用途都在编程之外：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，以及为八岁和十岁孩子制作有关密室逃脱与火蝾螈的可打印书籍。Skill 没有编程限定。学习目的、资料、最近发展区和练习适用于任何领域。代码场景中，用户反馈熟悉陌生代码库或新团队技术栈的价值，比从零学习语言更大。

**应该用哪个模型？**
没有标准答案，反馈差异很大。用户报告较高的[推理投入](https://www.aihero.dev/ai-coding-dictionary/effort)比中等设置产出更好的课程。一位用户通过 Copilot CLI 使用 Codex 运行同一 skill，只得到 30 行 HTML 卡片，而 Claude Code 产出完整课程。组织允许添加 skills 时，它可以原样运行在 Claude Cowork。如果课程太薄，先换模型、[代理运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)或推理投入，再考虑重写提示词。

## 有效运行的表现

- 空目录中，首先访谈你为什么学习，而非直接生成课程。
- `RESOURCES.md` 先于课程填充，每节课都列出一个值得亲自阅读的一手来源。
- 课程中的断言带外部链接；没有引用意味着凭记忆教学。
- 一节课可以一次学完，让你获得一项之前不会的能力。
- 在目录中打开新会话，说“下一课”，会接着课程继续，而非重头开始。
- `learning-records/` 持续增加，课程不再重复教授你已证明掌握的内容。
- 课程看起来属于同一系列：链接 `assets/` 中的样式表，而非各自携带样式。
- 需要判断的问题，会推荐论坛、subreddit 或课堂，而非只给答案。

## 在流程中的位置

`teach` 是一个**随时可用的独立工具**。它不属于构建流程，也不与工程流程共享产物。只要你还在学习主题，它就持续在自己的目录中工作。

它真正相邻的工具是 [handoff](https://aihero.dev/skills-handoff)。两者共同回答“被追问到不理解的内容怎么办”：用 `/handoff` 交接到教学工作区，在那里用 `/teach` 学习，再返回原处继续，避免停止追问来学习。另一个相近选择是 [research](https://aihero.dev/skills-research)，适用于需要带引用的文档，而非课程和记忆训练的情形。不确定哪个 skill 或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会帮你选择。
