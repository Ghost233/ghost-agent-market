## 作用

`wizard` 生成交互式 Bash 脚本，逐步引导人类完成手动流程，例如接入第三方服务、执行一次性迁移，或把项目从状态 A 转到状态 B。它打开每个 URL，说明点击和复制什么，收集返回值，写入 `.env` 文件和 GitHub Actions secrets。

[代理](https://www.aihero.dev/ai-coding-dictionary/agent)只编写脚本，绝不运行。由你在自己的机器上运行。向导是一个程序，不是操作说明列表。脚本按顺序运行步骤，保留输入值；你的工作是点击、粘贴、按回车。

## 使用时机

你可以输入 `/wizard`，代理也能自主使用它。遇到必须由你执行的步骤，例如它无法创建密钥或无法点击控制台时，代理会构建向导，而非把说明写进聊天、随后滚出视野。

下一个阻碍需要到控制台操作时，使用它：

| 情况 | 向导的工作 |
| --- | --- |
| 新开发者要配置六个服务，应用才能启动 | 依次打开控制台，收集密钥，写入 `.env` 和 CI |
| 一次性迁移要按特定顺序切换开关 | 将不可逆步骤按顺序放在确认关卡之后 |
| 项目只需一次从状态 A 转到状态 B | 引导转移，报告未能完成的部分 |
| 你正准备把这些步骤写进 README | 改写为可执行版本，步骤过时时会明确失败 |

决定构建什么时不用它，使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 和 [to-spec](https://aihero.dev/skills-to-spec)。

## 前提

生成向导没有前提。生成的向导在 Bash 上运行，某阶段设置 GitHub secret 或 variable 时使用 `gh`。缺少 `gh` 或尚未认证，运行不会失败，该阶段显示警告，结束摘要告诉你哪些内容要手动设置。

## 阶段

**阶段**是在一个屏幕上完成的一项集中任务。脚本在阶段之间清屏，因此某阶段超出一屏时，滚走的部分会丢失。按依赖顺序编写阶段，设置 `TOTAL_STAGES`，用来驱动进度显示。

[Skill](https://www.aihero.dev/ai-coding-dictionary/skill) 在编写任何脚本前，先确定流程范围。它先读仓库，不在不了解情况时提问：检查 `.env*`、`docker-compose*`、框架配置，以及 `.github/workflows/` 中每个 `secrets.*` / `vars.*` 引用。每个引用都对应向导必须产出的值。随后展示有序阶段列表，请你确认。确认后才将每阶段映射为人类实际执行的精确路径，例如“Dashboard → Developers → API keys → Reveal test key → copy”。不清楚当前 UI 时，询问你或查文档，不编造点击路径。

确定范围时，为每个收集值决定去向：

| 去向 | 条件 |
| --- | --- |
| 仅 `.env` | 本地开发需要，CI 不需要 |
| GitHub secret | CI 读取，且值敏感 |
| GitHub variable | CI 读取，且值公开 |
| `.env` 和 secret | 本地开发与 CI 都需要 |
| 不写入任何地方 | 阶段是纯操作，例如切换开关或升级套餐 |

## 模板已解决交互体验

[模板](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)提供完整体验：带剩余时间的进度、确认关卡、支持 WSL 的跨平台 URL 打开方式、密钥隐藏输入、幂等 `.env` 更新或插入、`gh secret` / `gh variable` 写入，以及列出所有跳过事项的结束摘要。`STAGES` 标记上方是固定库，每个向导中完全相同，绝不手动修改。库不改变，所以每个向导行为一致。每个向导只需确定流程范围、编写阶段。

编写向导的代理绝不从头到尾运行它，因为脚本会打开浏览器并等待人类输入。代理改做静态检查：`bash -n`、可用时运行 `shellcheck`，并逐项追踪每个值是否进入确定范围时约定的去向，每个 `set_secret` 名称是否匹配 CI 中真实的 `secrets.*` 引用。因此首次运行由你执行，这次运行也是测试。

## 默认临时使用

| 情况 | 脚本处理方式 |
| --- | --- |
| 一次性迁移、个人设置，或不会重复的转移 | 保存到临时路径或 `scripts/`，运行后删除 |
| 后续加入仓库的人也需要的设置流程 | 提交，并从 README 链接，让他们运行脚本，无需再次询问代理 |

## 常见问题

**API 密钥会进入模型上下文吗？**

不会。代理只编写脚本，不运行。你自己运行脚本，它通过终端隐藏输入收集密钥，直接写入 `.env` 或 `gh secret`。向导是 CLI，模型没有连接到它。这只适用于运行时由向导收集的值。确定流程范围时，把密钥粘贴进聊天，它会和其他粘贴文本一样进入[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。

**能退回去修正输错的值吗？**

运行途中不能，没有返回按钮。阶段向前执行，第 3 阶段输错意味着 Ctrl-C 后重跑。重跑成本低，因为已写入 `.env` 的值会作为默认值再次提供，正确阶段只按回车，错误处重新输入。用户在发布第一周就询问过，问题仍未解决：“很喜欢。不过，有办法返回去修正已输入的内容吗？”

**它知道我已经配置了什么吗？**

部分知道，但比发布时用户的反应所假定的少。提问前读取仓库，包括 `.env` 文件、`docker-compose`、框架配置和 CI 的 `secrets.*` 引用，因此针对缺失值确定范围，无需像 README 一样从零开始。但它不检查第三方服务。`.env` 已有密钥时，向导再次提供它，回车保留；已经创建 Stripe 账户却从未保存密钥时，向导仍让你进入控制台获取。

**它在工作流哪里，在 grilling 和 spec 之后吗？**

没有固定位置。它是独立工具，不是流程步骤。常见猜测是 `/grill-with-docs → /to-spec → /wizard`，这个顺序可以，但触发条件是出现手动流程，可能在开始前、构建途中，或交付很久之后。它也可作为发现工具：确定范围时，会先找到任务隐藏的前提，例如你没想到的三个 API 密钥，再让你决定是否接下工作。

**能在 Claude Code 以外使用吗？**

脚本可以。它是普通 Bash，无论由哪个[代理运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)生成，都以相同方式运行。Skill 本身是模型调用型，因此处处会列出：Claude Code 中输入 `/wizard`，Codex 中输入 `$wizard`，或直接描述卡住的设置。模型调用型也避开了 [#693](https://github.com/mattpocock/skills/issues/693)：Claude 桌面和 Web 应用会从[模型](https://www.aihero.dev/ai-coding-dictionary/model)列表中删掉**用户调用型** skills，并显示未安装。

**以前不是用户调用型吗？**

是。现在改为模型调用型，遇到必须由你执行的步骤时，代理会主动使用。以前能做的仍可做。模型调用让代理也能调用 skill，不影响你原有的 `/wizard` 用法。这个变更修复了一种失败：以前代理在构建途中被凭据阻挡，会往聊天中丢六个编号步骤，让你手动跟随；现在它编写向导。

**以前在 `in-progress/`，现在在哪里？**

从 v1.2 起位于 `engineering/`。它已脱离 beta 分类，在插件中正式发布，随其余正式内容一起安装，无需单独安装。进入正式分类时行为未改变。

## 生效迹象

- 任何脚本创建前，你已看到有序阶段列表和各阶段产出的值，并被要求确认。
- 询问来自某页的值之前，已打开该页 URL。不会要求你粘贴尚未让你去获取的内容。
- 密钥输入不可见，敏感内容不回显到终端历史。
- 每阶段适合一屏，仍需要的信息没有滚走。
- Ctrl-C 后重跑，可继续此前工作，将已保存值作为默认值提供。
- 最后屏幕列出写入内容，并单独列出未能完成、需要你手动处理的内容。

## 所处位置

`wizard` 是随时可用的独立工具，位于自动化停止、人类必须点击的边界。最接近它的是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，两者都让仓库进入可工作状态。后者配置本 skill 集合，`wizard` 为其他内容生成设置流程。它也与 [implement](https://aihero.dev/skills-implement) 配合：功能构建后需要凭据或手动切换时，由向导负责只能人类完成的步骤。不确定此时哪种 skill 合适，由 [ask-matt](https://aihero.dev/skills-ask-matt) 路由。
