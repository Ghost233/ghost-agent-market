## 它的作用

`diagnosing-bugs` 对棘手缺陷或性能回退执行六阶段诊断：建立复现、最小化、排序假设、插桩、通过回归测试修复、清理。

在存在**紧凑**反馈循环之前，它不允许代理形成理论：一个命名的命令，已运行至少一次，能在*这个*缺陷存在时变红、修复后变绿。编码代理默认收到缺陷报告就读代码并猜测，本 skill 阻止这一点。没有能变红的命令，就没有阶段 2。这一道门禁就是 skill 的目的。循环存在后，后续的二分、假设检验、插桩都是机械操作。

## 何时使用

输入 `/diagnosing-bugs`，或任务适合时代理自行使用。它由模型调用，在“diagnose”“debug this”或报告某处损坏、抛错、失败、缓慢时触发。

用于困难问题：一眼无法解决、间歇性不稳定、在两个已知正常状态之间引入的回退。它有意缓慢而彻底，因此不适合希望一条消息就得到答案的问题。

| 你的情况 | 去哪里 |
| --- | --- |
| 可以用症状描述的具体缺陷 | 本 skill |
| 慢端点，或有已知前后状态的耗时回退 | 本 skill；有性能分支：测量基线，再二分 |
| “代码库瓶颈在哪里？”，没有具体症状 | 不用本 skill。它诊断一个已知失败，不做审计 |
| 他人的原始缺陷报告，尚未确认或整理 | 先 [triage](https://aihero.dev/skills-triage) |
| 为回答设计问题编写一次性代码，而非追查缺陷 | [prototype](https://aihero.dev/skills-prototype) |
| 测试先行构建计划行为 | [tdd](https://aihero.dev/skills-tdd) |
| 修复后询问怎样才能预防这个缺陷 | 同一会话运行 [retro](https://aihero.dev/skills-retro) |
| 没有合适接缝来锁定缺陷 | 自行启动 [improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) |

## 紧凑循环就是这个 skill

阶段 1 投入最多，因为它是唯一困难的阶段。skill 大致按偏好顺序列出建立循环的方法：

1. 在能触及缺陷的任何接缝上建立失败测试。
2. 对运行中的开发服务器执行 curl 或 HTTP 脚本。
3. 用固定输入调用 CLI，与已知正确快照比较。
4. 无头浏览器脚本，对 DOM、控制台或网络断言。
5. 回放采集内容：保存的请求、载荷或事件日志，隔离执行代码路径。
6. 一次性测试框架：系统最小子集，一次函数调用。
7. 属性测试或 fuzz 循环，处理“有时输出错误”。
8. 可交给 `git bisect run` 的二分测试框架。
9. 差分循环：同样输入，比较旧版与新版。
10. [人参与循环](https://www.aihero.dev/ai-coding-dictionary/human-in-the-loop)的 Bash 脚本，作为最后手段。skill 提供 `scripts/hitl-loop.template.sh`：代理运行脚本，你在终端按提示操作，答案作为可解析输出返回。

目标不只是*有*循环，而是**紧凑**：快（数秒）、确定（每次结论相同）、精确（断言原始症状，而非“没崩溃”），并可由代理独立运行。耗时 30 秒又不稳定的循环几乎不比没有循环好。只偶尔出现的缺陷，目标不是干净复现，而是**提高复现率**：循环触发、并行、加压力、插入 sleep，直到失败率足以支持调试。

无法建立循环时，skill 要求代理停下说明，列出尝试，并请求[环境](https://www.aihero.dev/ai-coding-dictionary/environment)访问、采集工件，或临时插桩许可。它不得继续形成假设。

## 阶段之间的门禁

各阶段是门禁，不是清单。条件成立前，代理不能进入下一阶段。

| 门禁 | 必须成立的条件 |
| --- | --- |
| 进入阶段 2 | 一个命名命令，已运行并粘贴输出，能在这个缺陷上变红 |
| 进入阶段 3 | 已复现*且*最小化：所有剩余元素都对复现必要 |
| 进入阶段 4 | 已有 3–5 个排序后的可证伪假设，各自写明预测，测试前向你展示 |
| 进入阶段 5 | 探针对应具体预测，每次只变一个变量；所有调试日志带 `[DEBUG-a4f2]` 等标记，便于一次 grep 全部清理 |
| 完成 | 原始复现不再失败，插桩已移除，提交消息指出哪个假设正确 |

阶段 5 有一个例外。代理在修复前写回归测试，但必须存在**正确接缝**：测试能覆盖调用点实际出现的真实缺陷模式。唯一可用接缝太浅时，skill 要求说明，而不写制造虚假信心的测试。缺失接缝本身就是发现，应记录而不隐藏。

## 常见问题

**我只想直接得到答案，它却在简单问题上触发。**

这是报告最多的问题。尤其在 GPT-5.6-Sol，用户报告仅描述问题就触发正式诊断流程，先构造复现（往往是价值有限的模拟场景），再给回答或建议，导致明显延迟。[Issue #578](https://github.com/mattpocock/skills/issues/578) 有四人独立报告。接受的修复是先用轻量办法，只在问题需要时进入完整诊断，但尚未发布。skill 按 Claude Code 的调用行为调优，触发阈值较低的[模型](https://www.aihero.dev/ai-coding-dictionary/model)会过于频繁地使用它。修复发布前，可明确要求“直接回答，不要诊断”，或在[运行框架](https://www.aihero.dev/ai-coding-dictionary/harness)禁用模型自动调用。

**能让它检查代码库中的性能问题吗？**

不能。它诊断你已能指出的单个失败。性能分支处理有症状的回退：建立基线测量，再二分，先测量后修复，而非主动扫描。主动版本曾被[提议并关闭](https://github.com/mattpocock/skills/issues/431)，目前没有 skill 执行它。

**写修复之前会停下征求我的意见吗？**

不会。只有阶段 3 有人工检查点：测试任何假设前展示排序列表，你离开时代理按自己排序继续。插桩与修复之间没有门禁，因此未征得你对根因的认同，它就可能开始写代码。[Issue #124](https://github.com/mattpocock/skills/issues/124) 请求这一门禁，仍未关闭。需要时在调用中说明。

**我已对报告运行 `/triage`，是否重复？**

部分重复，两个 skills 都没说明。一位读者指出，triage 第 3 步基本是 diagnosing-bugs 阶段 1–2 的浅层、有界版本，但两份文件互不提及。Triage 有界检查“是否真是缺陷、涉及什么表面”，本 skill 做彻底版本。先 triage 并不浪费，验证常提供阶段 1 的大部分原料；但应预期本 skill 完整重做，也不会有交叉引用提醒。

**它粘贴的复现输出会泄密吗？**

可能。skill 要求粘贴命令与输出，并索要 HAR、日志转储、core dump 等工件，却没有清理敏感信息的指令。[Issue #674](https://github.com/mattpocock/skills/issues/674) 指出凭据、token、cookie、个人数据可能进入聊天、issue 或 PR，提议增加脱敏护栏，仍未实现。目前脱敏由你负责，尤其是公开输出之前。

**安全扫描器把这个 skill 标为高风险。**

Snyk 会标记，这是误报。它是整套中唯一附带可执行 Shell 脚本（`hitl-loop.template.sh`），同时要求运行脚本并 curl 开发服务器的 skill。`.sh` 文件、运行指令与出站 HTTP 足以触发静态扫描器。脚本本身约 30 行 `read -r -p` 提示，暂停等待人工输入。扫描器评估可能的能力，而非已证实的漏洞利用。

**`/diagnose` 去哪里了？**

v1.0.0 重命名为 `/diagnosing-bugs`，旧名不再存在。你自己的包装 skill 或保存提示若串联 `/diagnose`，需更新。

## 正常工作的表现

- 提出任何理论前，先展示命令及红色失败输出。先给理论说明 skill 没有执行。
- 复现的是你报告的失败，而不是途中发现的相近问题。
- 猜测前先缩小复现，并能解释每个剩余部分为何必要。
- 测试前展示 3–5 个排序假设，各自带可证伪预测。
- 新增调试日志都带 `[DEBUG-a4f2]` 等标记，宣告完成时 grep 无结果。
- 提交或 PR 消息说明哪个假设正确。
- 无法用测试锁定缺陷时明确说明，而不写浅层测试。

## 它在流程中的位置

`diagnosing-bugs` 是随时可用的独立工具。某处损坏时启动，修复和回归测试完成后结束。不保留状态，无需事先配置。[ask-matt](https://aihero.dev/skills-ask-matt) 把“某处损坏”路由到这里。

两个邻居很重要。[retro](https://aihero.dev/skills-retro) 在它之后：修复后同会话运行，趁已有比开始时更多的信息，询问怎样预防。`diagnosing-bugs` 不会自行调用 `retro`，因为 `retro` 只能由用户调用。[triage](https://aihero.dev/skills-triage) 用于他人原始报告，在它之前执行同样前两个阶段的浅层版本。
