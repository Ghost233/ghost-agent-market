# 任务示例

任务按其解决的问题分组。每项列出启动运行的触发器、运行内容和接下来触发的工作。大多数工厂从其中一项开始，再逐步串接其他任务。

## 未分诊的工单不断堆积

**探索任务**

- 触发：创建工单，或人给工单添加标签。
- 工作：对照代码库核查工单中的说法，尽可能复现，分类为容易决策、需要人介入或不是缺陷，并把发现留在工单中供实施者使用。它从不推送代码。
- 后续触发：对容易决策的工单触发实施运行；其他工单标记为等待人处理，然后结束。

## 已就绪的工单等待实施

**实施任务**

- 触发：人或探索运行将工单标记为就绪。
- 工作：实施工单，直到自动检查通过，然后创建草稿 PR。
- 后续触发：自动审查运行。

## PR 等待审查

**自动审查任务**

- 触发：PR 创建后还没有自动审查，或人给它添加标签。
- 工作：对照代码库标准和来源工单审查 diff。
- 后续触发：未通过时触发返工运行；通过时结束，PR 等待人工审查和人工合并。

## 自动审查未通过，却一直没有修复

**返工任务**

- 触发：自动审查运行判定 PR 未通过。
- 工作：只修复自动审查指出的问题，然后推送。
- 后续触发：自动审查运行。失败达到设定次数后结束，并把 PR 标记为等待人处理。

## 规格过大，无法一次运行完成

**拆分任务**

- 触发：给规格工单添加标签。
- 工作：把规格拆成工单，每张记录依赖的工单。
- 后续触发：实施运行。

这里的实施运行领取下一张依赖全部关闭的工单，完成后再次触发自身，直到没有剩余工单。

## 迁移到更严格的自动检查

启用新的 lint 规则或更严格的类型设置，但只有部分文件通过。规则先约束已通过的文件，未通过的文件放在例外清单中。

**渐进收紧任务**

- 触发：每天定时运行。
- 工作：从例外清单取出一个文件，修复到通过更严格的检查，然后创建 PR。
- 后续触发：自动审查运行。例外清单为空时，没有文件可领取，迁移完成。

每天一个小 PR 能降低人工审查成本，检查只会越来越严格。

## 用户报告缺陷，却无人阅读

应用中的反馈按钮是工单来源：每份报告创建为一张已带探索标签的工单，后续交给探索运行。

## 生产问题发现得太晚

监控器（例如慢查询或错误率监控）是工单来源。每个问题创建一张工单；再次发现同一问题时，在已有开放工单下评论。修复合并后问题仍然存在，就重新打开工单。

## 工厂自己的运行失败

**修复任务**

- 触发：编排器报告一次运行失败。
- 工作：把失败日志提交为工单；失败可修复时，尝试通过 PR 修复。
- 后续触发：自动审查运行。修复运行自身失败时不触发任何工作，避免修复任务相互连锁。由于它修改工厂自身，始终需要人工审查。

## 代码库逐渐偏离预期

**架构任务**

- 触发：每晚定时运行。
- 工作：扫描近期变更，将重构候选项汇总为一张工单。
- 后续触发：无。由人选择候选项并添加标签，启动通常的后续流程。

## 同样的错误反复出现

**复盘任务**

- 触发：PR 合并，限制为每合并十个 PR 触发一次。
- 工作：读取 PR、工单、自动审查和运行日志，通过 PR 提出对工厂自身指引的修改。
- 后续触发：自动审查运行。
