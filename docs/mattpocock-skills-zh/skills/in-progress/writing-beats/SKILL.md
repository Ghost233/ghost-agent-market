<what-to-do>

用户已经或即将提供原始素材的 Markdown 文件。这是**利用（exploit）**阶段：探索已完成，素材堆已固定。选定一条穿过素材的路径，挖掘素材来填充每个节拍。

用户没说文章保存在哪里时，只问一次并记住路径。

随后逐节拍展开旅程，采用自选冒险的方式：

1. **确立前提。** 开始任何节拍前，先与用户确定受众进入文章时已经知道什么，即从一开始就**建立基础**的概念。其余概念必须由某个节拍建立基础，后续节拍才能使用。见[建立概念基础](#grounding)。
2. 从原始素材中写出 2～3 个候选**起始节拍**，各自作为不同的文章入口。每个只依赖已有基础的概念，并注明它新建立哪些概念。在写入文章文件前，展示节拍，由用户选择。预告这一选择会解锁哪些节拍，让用户能看到路径稍远处的情况。
3. 用户选定起始节拍后，将**仅这一个节拍**写入文章文件。节拍可以是一句话，也可以是多段，取决于它自然需要的形式。写完就停。
4. 从磁盘重读文章文件。随后提供 2～3 个候选**后续节拍**，对应从文章当前位置转向的不同方向。每个都必须能从当前已建立基础的概念集合触达，并注明它建立哪些概念。
5. 循环步骤 3～5，直到文章自然结束。

</what-to-do>

## 建立概念基础

每个**概念**都必须先**建立基础**，节拍才能依赖它：受众进入时已知道，或在更早节拍中已见过。使用没有基础的概念会丢失读者，这种动作是旅程唯一不能采用的动作。单位是概念，不是表达它的词：即使没有术语，节拍也可能依赖读者缺少的想法。概念有名称，也就是**术语**时，建立基础意味着让想法和术语一起被理解。

概念通过两种方式建立基础：

- **前提**：第一个节拍之前已有基础，由受众带入，在开始时固定。
- **引入**：某个节拍建立它，此后所有节拍都可视为已有基础。

因此每个节拍做两件事：**要求**已有基础的概念，并为新概念**建立基础**。持续记录当前已有基础的概念，每个节拍落地时更新列表。

这决定自选冒险的形状。候选节拍只有在所有依赖概念都已有基础时才可触达；选择一个建立概念 X 的节拍，会解锁所有等待 X 的节拍。提供后续节拍时，每个都必须能从当前集合触达，并说明会建立哪些概念，让用户看到它打开哪些路径。

主要选择是把哪些概念列为前提，哪些在文中建立。开头要求太多，会排除缺少基础的读者；文内建立太多，会让早期节拍淹没在定义中。确立前提时与用户商定。某个诱人的节拍需要尚无基础的概念时，重新评估：先增加建立基础的节拍，或将概念提升为前提。

## 节拍是什么

节拍是旅程中的一个动作，只做一件事：设置场景、表达观点、提出问题、加一段旁注、改变角度。然后停止，让读者处在下个节拍可以转向的位置。

节拍的长度由需要决定：

- 只需一个动作时，用一句话，例如“然后连续三周什么都没发生。”
- 需要铺垫时，用一个短段。
- 节拍是独立小故事、论证或示例时，用多段。

一个“节拍”若需要五段和三个小标题，就是两个节拍粘在一起，应拆开。

## 从素材堆取材

从原始素材堆取出内容，填充每个节拍。可以改写、拆分、重组或引用。素材堆就是采石场。

## 结束旅程

旅程完成时，文章结束，无需用空素材堆。多数素材堆会剩下未入选的碎片。这没问题，准备比实际需要更多的素材，就是为此。

## 写作节奏

- 每次追加一个节拍，绝不提前写后面的内容。
- 每次写入前从磁盘重读文章文件，完全保留用户编辑。
- 用户大幅改动之前的节拍时，让改动影响后续内容。
- 用户说“重写那个节拍”或“回去试另一个第 3 节拍”时，原地修改，其余内容保持不动。
