<what-to-do>

用户已经或即将提供原始素材的 Markdown 文件。把它当作输入素材堆，可为整齐的碎片列表、无结构的长篇文字或逐字记录。格式不重要。做其他事情之前，从头到尾读完。

随后开展塑形会话，产出单独的文章文档。这是**利用（exploit）**阶段：探索已完成，素材堆已固定。选定结构，挖掘素材来填充。不要编辑原始素材文件，对本 skill 而言它只读。

用户没说文章保存在哪里时，只问一次并记住路径。

</what-to-do>

<supporting-info>

## 循环

1. **阅读素材堆。** 完整读输入文件，了解其中内容。
2. **确立前提。** 与用户确定读者进入时已知道什么，即从开始就**建立基础**的概念。其余概念必须由某个内容块建立基础，后续块才能依赖。见[建立概念基础](#grounding)。
3. **拟出 2～3 个候选开头。** 每个暗示不同的主张或角度。全部展示，要求用户选一个或组合混合版本。选定的开头决定文章后面必须做什么。
4. **逐段生长。** 开头落定后，问“按照这个开头，读者接下来需要听什么？”从素材堆取材回答。下一块只能依赖已有基础的概念，并在落地时为新概念建立基础。讨论下一块的形式：段落、列表、表格、提示框、引用或代码块。每次形式选择都应有意为之，并能说明理由。
5. **边做边追加到文章文件。** 不批量写入。每个达成一致的段落或内容块立即写入，让用户看到文章成形。
6. **循环步骤 4，直到文章完成。** 用户决定何时完成。

<a id="grounding"></a>

## 建立概念基础

每个**概念**都必须先**建立基础**，内容块才能依赖它：读者进入时已知道，或在更早内容块中见过。使用没有基础的概念会丢失读者。单位是概念，不是表达它的词：即使没有术语，内容块也可能依赖读者缺少的想法。概念有名称，也就是**术语**时，建立基础意味着让想法和术语一起被理解。

概念通过两种方式建立基础：

- **前提**：开头之前已有基础，由读者带入，在开始时固定。
- **引入**：某个内容块建立它，此后整篇文章都可视为已有基础。

持续记录已有基础的概念。询问“读者接下来需要听什么？”时，若下一步需要尚无基础的概念，这个概念本身就是答案。先在此处或更早内容块建立它，否则无法继续。这是[从素材堆取材](#pulling-from-the-pile)中指出缺口的更上一层：那里是素材缺失，这里是文章缺少基础。

主要选择是把哪些概念列为前提，哪些在文中建立。开头要求太多，会排除读者；文内建立太多，会让开头淹没在定义中。确立前提时与用户商定。

## 对话感

这是反向的 grilling。构思时的问题是“你实际观察到了什么？”这里变成“这篇文章到底论证什么，读者需要按什么顺序听？”提出异议，不放过薄弱转场。一个段落没有存在理由，就删去。

反复使用这些动作：

- “这段为读者做了什么，而上一段没有做到？”
- “删掉这段，哪里会出问题？”
- “这里该用段落还是列表？为什么用段落？”
- “这句做两件事，拆开或选一个。”
- “开头承诺 X，现在偏向 Y。重新串起来，或改开头。”

<a id="pulling-from-the-pile"></a>

## 从素材堆取材

把原始素材当作采石场，而非脚本。取出碎片，改成适合周围段落的文字，再放进去。一个碎片可拆入多段、与其他碎片合并或改写。素材堆的用途是供挖掘，文章则要读起来像同一个声音。

素材堆缺少文章需要的内容时，明确指出缺口：“这里需要示例，素材中没有。现在给我一个，否则删除这一节。”

## 必须讨论的形式选择

选择内容块的表达形式时，与用户明确讨论以下权衡，不默默决定：

- **段落与列表。** 段落承载论证，列表承载并列条目。条目并不真正并列时，段落更好；真正并列时，列表更易扫读。
- **正文与提示框。** 技巧、警告和旁注只有在放入正文会打断主论证时，才放在提示框（`> [!TIP]`、`> [!NOTE]`）。否则留在正文。
- **表格与重复结构。** 相同字段、相同结构重复 3 次以上，用表格；否则用粗体开头的段落。
- **引用与改写。** 原始措辞本身是重点时引用，只有想法重要时改写。
- **代码块与行内代码。** 多行、可运行或用于说明的代码用块；单个 token 或标识符用行内代码。

## 写作节奏

每个内容块达成一致就追加到文章文件。每次写入前从磁盘重读，用户可能在轮次间编辑。绝不盲目覆盖。用户要求重写段落时，只原地编辑指定段落，其余保持不动。

## 不属于范围

- 挖掘素材堆中没有的新碎片，缺口按“从素材堆取材”处理。
- 编辑原始素材文件。
- 发布、针对特定平台排版，或添加用户未要求的 frontmatter。
