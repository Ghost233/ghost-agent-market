# 贡献

每个 issue 都以 [`SCOPE.md`](./SCOPE.md) 的门槛判断。请先阅读。

## 请求提交到哪里

| 请求 | 入口 |
| --- | --- |
| skill 的缺陷 | [缺陷 issue](https://github.com/mattpocock/skills/issues/new?template=bug.yml) |
| 修改现有 skill | [想法或反馈 issue](https://github.com/mattpocock/skills/issues/new?template=idea.yml) |
| 问题或使用方法 | [讨论：Q&A](https://github.com/mattpocock/skills/discussions/categories/q-a) |
| 新 skill 的想法或希望贡献的 skill | [讨论：Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas) |
| 支持其他宿主或 issue 跟踪器 | 先阅读 [`.out-of-scope/`](./.out-of-scope)，再到 [讨论：Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas) |

Pull Request 仅对协作者开放，因此请在 issue 中描述修复方法。

## 用 AI 编写的 issue

欢迎代理协助，但由你发布 issue，也由你负责：

- **每个 issue 一个问题。** 一次会话发现多个问题，就分别提交 issue，也可以不提交。
- **保持简短。** 一屏放不下就精简。
- **复现步骤在前。** 展示问题的步骤应先于分析。
- **不粘贴规格全文。** 不提交完整提案、计划或重写后的 `SKILL.md`。描述问题，由维护者设计修复。
- **不要提交你自己项目的 issue。** 如果代理把你的项目规格或工单提交到这里，说明它选错了仓库。请在你的项目中运行 `/setup-matt-pocock-skills`。
