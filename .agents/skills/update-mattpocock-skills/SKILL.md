# 更新 Matt Pocock Skills

本 skill 是 `ghost-agent-market` 的仓库级维护入口，保存在 `.agents/skills/`。
使用仓库内的上游子模块和中文源，按下面四步完成更新。
开始前读取根目录指引，以及 [仓库映射与验证入口](references/repository-map.md)。
路径均相对仓库根目录；通过 `git rev-parse --show-toplevel` 确定根目录。

## 1. 更新子模块，记录并输出版本差异

1. 记录主工作区和 `upstream/mattpocock-skills` 的分支、状态、未跟踪文件。
   保存父仓库 gitlink、子模块实际 HEAD、各插件原版本，作为本轮基线。
   子模块未初始化时，先确认目录没有用户文件，再初始化至父仓库固定提交。
   实际 HEAD 与 gitlink 不同或相关路径已有用户改动时，先查明来源；保留这些改动。
   需要覆盖用户文件才能继续时，列出具体文件并等待用户决定。
2. 拉取该子模块 `origin` 的分支和标签。用户指定 ref 时使用该 ref；否则通过
   `git ls-remote --symref origin HEAD` 确认上游默认分支。
   将目标解析为完整 SHA，并在本轮固定使用它。读取新旧 SHA 的插件清单版本和标签。
   验证旧提交是目标的祖先；出现分叉或上游历史改写时，说明差异并等待用户决定。
3. 在切换前生成差异报告：完整新旧 SHA、上游版本与标签、提交数量和列表、
   文件增删改及重命名、稳定 skill 清单变化，以及需要翻译或适配的行为变化。
   上游版本号相同也必须比较提交与文件。
   保存到 `docs/mattpocock-updates/<UTC时间戳>-<旧SHA前7位>-<新SHA前7位>.md`，
   随即向用户输出版本差异和报告路径，再继续后续步骤。
4. 将子模块检出到固定目标 SHA，核对子模块 HEAD 与目标相等。
   目标与基线相同时，仍检查现有翻译及生成包是否有遗漏；全部一致时报告无需更新。

**完成标准：** 子模块位于固定目标，差异已保存并展示，基线和用户原有改动可追溯。
中断后继续同一轮时，沿用报告中的原基线和目标，避免重复递增版本。

## 2. 翻译 skills 和相关资料

1. 枚举目标提交全部受跟踪文件，确定与 skills、使用及维护有关的资料范围。
   包括 `skills/**`、`docs/**`、README、CHANGELOG、GLOSSARY、范围说明、
   上游 `CLAUDE.md`/`AGENTS.md`、相关隐藏目录、脚本、调用策略和授权文件。
   递归跟踪这些文档的本地链接，纳入参考资料、模板和其他支持资源；
   排除无关文件时记录原因。上游维护指引作为翻译来源，执行仍遵循本仓库指引。
   对照现有中文内容建立“上游路径 → 中文路径 → 平台产物”的覆盖表。
   首次补齐缺失译文；后续按 diff 更新，并保留未变文件的已有译文。
2. 已发布 skill 的范围取目标上游插件清单的 `skills` 列表。
   将每个 skill 及其资源映射到两端中文插件的同名目录。
   未发布、实验中和退役内容也纳入翻译覆盖表，放入参考目录并保留其状态标记；
   安装插件的清单只包含上游实际发布的 skill。
   独立资料按上游相对路径保存到 `docs/mattpocock-skills-zh/`。
3. 翻译自然语言，保留标识符、文件名、配置键、命令参数和接口语义。
   脚本保持行为和执行权限，翻译其说明、注释及适用的用户提示。
   保留 MIT 授权原文与出处。
   逐项核对触发条件、步骤顺序、完成标准、委派要求和调用策略，避免遗漏条件或改变要求强度。
4. 按现有平台差异同步 Claude Code 和 Codex：共享译文含义一致，
   平台调用语法和 UI 元数据分别适配；Codex 的显式调用限制落到 `agents/openai.yaml`。
   调整本地链接，使安装包内每个 skill 能独立读取它所需的资源。
   按仓库中文写作规范校对，并在覆盖表中说明平台差异和保留原文的原因。

**完成标准：** 每个上游 skill 和相关资料都有处理记录，发布内容完整，资源与链接可达，
译文逐项保留上游行为约束。

## 3. 更新所有相关插件

1. 同步 Claude Code、Codex 和 DSH 的 Matt 插件。
   从 Codex 中文源生成 DSH，使用仓库现有构建入口；核对并移除本轮退役的生成内容。
   生成器只复制现有源，不能以“构建成功”代替对残留文件的检查。
   ZCode 沿用 Claude marketplace；以当前仓库检索结果补充其他实际发布入口。
2. 每个发生修改的插件从本轮原基础版本增加 `0.0.1`，按根目录的十进位规则进位。
   Codex 随后更新 `+codex.<UTC timestamp>` 后缀。
   已有的平台版本差异写入报告；插件版本独立于上游版本。
   使用现有适用于 Matt 的 cachebuster；没有时只定点修改 Matt 清单。
   `tooling/update-ghost-agent-skills.mjs` 的目标是另一插件，不用于本轮 Matt 更新。
3. 同步所有发布同一插件的 marketplace 清单，核对各根目录下的 `source` 实际路径，
   以及清单版本和对应插件版本。同步 README 的上游 SHA、版本、skill 数量和安装说明，
   更新 DSH 包版本、目录和来源指纹。
   上游清单数量变化时，按真实增删同步构建器及测试的范围断言。
4. 运行本次变更涉及的完整本地检查，记录命令、源码状态、真实退出码和结果。
   先运行失败用例或最小所属任务，修复后再验证受影响范围及必需检查。
   缺失环境或超时如实记录；提交或远端补验遵循会话授权与仓库门禁。

**完成标准：** 所有相关发布入口、版本、资源、生成产物和文档一致，适用的本地检查全部通过。

## 4. 用一个子代理审查，修复问题

派发一轮独立、只读的子代理审查。提供用户请求、本轮报告、新旧上游 SHA、
全部修改文件、翻译覆盖表、平台适配约定和验证记录。
子代理负责审查，主代理负责修复；说明它与主代理共享工作区，保持现有改动。

要求子代理对照原始上游差异审查：

- 翻译是否完整，是否改变条件、顺序、要求强度、委派行为或调用策略。
- 新增、退役和未发布 skill 的处理是否与上游清单一致，支持资料是否漏译。
- 各插件、清单、版本、链接、授权、生成文件及文档是否一致。
- 检查是否覆盖最终内容，是否把环境故障或旧结果当作成功。
- 是否误改用户文件、无关插件，或越过本轮授权范围。

让子代理返回有路径、证据和影响说明的 P0/P1/P2 问题；没有问题时明确报告无发现，
并说明审查限制。主代理修复每项有效问题，记录处理结果；不采纳的项说明证据与理由。
修复后重跑受影响检查，必要时重新生成产物，并让完整验证覆盖最终内容。
委派能力缺失时，说明具体限制，保留审查待办，不宣称四步已完成。

**完成标准：** 一轮子代理审查有可读结果，有效问题已修复，最终验证通过，报告已补全。
交付时输出新旧上游提交与版本、翻译覆盖和行为变化、各插件版本、审查与修复结果、
验证记录、最终工作区状态及剩余限制。
提交、推送、发布和安装遵循当前会话授权；发生远程更新时完成涉及本地分支的同步核验。
