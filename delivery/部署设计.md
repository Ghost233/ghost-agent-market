> 上游输入：《系统设计》v1.0（G4 已批准；§0.1 声明 §4 数据库 / §5 部署架构 / §6 网络架构整节略过，本《部署设计》为权威的本地运行时拓扑文档）、《高层架构设计》v0.2（G3 冻结 D1~D5）、security-architect Step1 骨架结论。

## 1. 引言

### 1.1 适用范围与部署形态

- **系统定位**：workbuddy 专家团（Expert Team）设计规范与编排模型，作为 goal-dag v5 子线程体系的本地演进。
- **部署形态**：本地插件规范（文件型 registry + Node.js 运行时进程组），以 git 仓库形式经三端 market 分发；端用户从对应 market 安装后在**本机进程空间**运行，状态源为本地文件（`progress.json` / `events.jsonl`），不依赖任何中心化服务。
- **运行边界**：非 SaaS、非多租户；以专家团会话（`{session}/`）作为会话级 tenantId 隔离载体（详见 §3 / §7）。
- **外部唯一入口**：仅 ZCode 端 `install-agents.py` 在线安装通道使用 HTTPS（GitHub raw），其余交互全部本地完成，不强制联网。
- **本文档权威范围**：因《系统设计》§5/§6 整节略过，本文档是本地运行时拓扑、文件边界、进程隔离、发布运维的唯一权威描述。

## 2. 环境与资源清单

### 2.1 环境矩阵

本部署设计覆盖 dev / int / uat / prod 四套环境矩阵，环境间以**本机目录 + Git 分支 + 独立 profile**做进程级与文件级隔离（无 VPC/账号隔离概念）。

| 环境 | 用途 | 集群隔离（本地适配） | 数据 | 网络访问 |
| --- | --- | --- | --- | --- |
| dev | 开发自测 | 单开发者本机工作目录（git feature 分支） | 模拟数据（本地临时文件） | 本机（local） |
| int | 联调 | 独立本机 profile + 独立 git 集成分支 | 模拟数据 | 本机（local） |
| uat | 预发 / 验收 | 独立本机 profile + 非系统盘备份副本 | 仿生产（脱敏专家定义） | 本机（local）+ 白名单 |
| prod | 生产 | 独立本机正式 profile + 非系统盘备份 | 真实数据 | 本机 + ZCode 在线 HTTPS 安装通道 |

> **本机隔离策略**：四环境共享同一套运行时二进制，但通过①独立 `{session}/` 目录、②独立 expert-registry 副本、③独立 git 分支（main 用于 prod，release/* 用于 uat/int，feature/* 用于 dev）三重隔离；prod 数据落非系统盘备份副本，RPO ≤ 5 min、RTO ≤ 10 min（对齐《系统设计》§7.2.5）。

**安全组 → 文件权限映射（与 security-architect Z-* 完全一致）**：

| 安全区（Z-*） | 信任域 | 文件 / 资源 | 权限 | 敏感度 |
| --- | --- | --- | --- | --- |
| Z-PUBLIC（L1） | TD-1 | `experts/{id}/expert.md`、`registry/expert-registry.json`（读）、`skills/`（只读） | 0644 | 公开 |
| Z-GOV（L2） | TD-1/TD-2 | `registry/expert-registry.json`（写，文件锁） | 0644 + fs.lock | 内部 |
| Z-STATE（L2/L3） | TD-3 | `{session}/progress.json`（0644）/ `{session}/events.jsonl`（0600） | 0644 / 0600 | 状态 |
| Z-WRITE（L3） | TD-2/TD-3 | `experts/{id}/worktree/`（执行专家写域） | 0700 | 敏感 |
| Z-KEY（L4） | TD-4 | `OS Keychain` / `~/.config/ghost/*.key` | 0600 | 高敏 |
| Z-DAEMON（L4） | TD-2 | `{session}/.dashboard/heartbeat.json` | 0600 | 高敏 |

> **边界 B1~B4**（信任域间跨域访问控制）：
> - **B1（TD-1 → TD-2）**：专家定义文件（Z-PUBLIC 0644）被编排进程（M3）读取；越权写被 ACL 校验拒绝（C403001）。
> - **B2（TD-2 → TD-3）**：编排/执行进程读写 `{session}/`（Z-STATE）；Dashboard daemon 仅只读（B2 单向）。
> - **B3（TD-3 → TD-4）**：daemon 运行需读取 OS Keychain 中的 model Key（Z-KEY 0600），经 Keychain ACL 授权。
> - **B4（TD-2 → 外部）**：ZCode 安装通道（R-N-002 HTTPS）为唯一外部边界，禁本地路径绕过。

#### 3.1.2 拓扑要素清单（本地适配）

- **跨机器部署 / 机器数量**：单机本机运行（无跨机器/跨 AZ）；三端（CC/Codex/ZCode）为分发副本，非运行实例复制。
- **跨 AZ / Region**：N/A（本地插件无 AZ/Region 概念）。
- **流量入口路径**：本机 CLI（stdio）→ M1/M2；唯一外部入口为 ZCode HTTPS 安装通道（R-N-002）。
- **内部调用路径**：M3 编排 → EX/M4；M4 → M2（ACL 校验）；M5 → {session}/（只读）。
- **状态源访问路径**：goal-dag → `{session}/progress.json`（0644）+ `events.jsonl`（0600）；M5 只读消费。

### 3.3 高可用与故障容错

#### 3.3.1 故障域划分

| 故障域 | 影响范围 | 容错机制 | 预期 RTO |
| --- | --- | --- | --- |
| 单进程（单执行专家子进程） | 单个 goal 执行 | Supervisor 看门狗重启子进程 | ≤ 10s（瞬时） |
| 单会话（{session}/） | 单个专家团会话全部状态 | 会话级状态文件重建 + registry 快照恢复 | ≤ 5min |
| 单机器（本机） | 该机器全部进程与文件 | 文件快照恢复（非系统盘副本）；专家定义由 Git 同步可重建 | ≤ 10min |
| 跨机器 / 跨端 | 多端分发一致性 | 三端 AGENTS.md 同步校验 + 滞后阻断重发 | ≤ 1h（同步窗口） |

> **可用性来源拆分**：IaaS/PaaS SLA 兜底 = 无（本机 OS 与磁盘由用户环境保障）；本系统自身保障 = 进程监管（Supervisor 重启）、文件快照恢复（RPO≤5min/RTO≤10min）、Dashboard daemon 心跳自愈（连续 3 次缺失 45s 触发重启）、审计链独立副本（≥1 年）。

#### 3.3.2 负载均衡（本地适配）

- 本系统为单本机串行编排（单 Main 不变量），无网络层 LB；等价机制为**进程监管 + 文件锁串行化**：
  - 4 层：N/A（无网络入口）；
  - 7 层：N/A（无 HTTP 服务）；
  - 等价保障：registry 单写文件锁（fs.lock，超时 5s）避免并发写冲突（C409001）；Dashboard daemon 单会话单进程（max_restart=5）。

#### 3.3.3 健康检查配置

| 检查对象 | 路径 / 方式 | 频率 | 失败阈值 | 连续成功阈值 |
| --- | --- | --- | --- | --- |
| Dashboard daemon | 读 `{session}/.dashboard/heartbeat.json` | 15s（Supervisor） | 连续 3 次缺失（45s）判 UNHEALTHY | 1 次心跳成功即恢复 RUNNING |
| 执行专家子进程 | Supervisor wait/notify 监听完成事件 | 事件驱动 | notify 超时 → 重启 | — |
| registry 可读性 | 启动期读取 `expert-registry.json` | 启动 + 每次写前 | 读取失败 → AL-01 告警 | — |

#### 3.3.4 弹性伸缩配置

- 触发指标：Node.js 进程 CPU / 内存 / 心跳文件增长 / 文件锁等待时长。
- 阈值与区间：本系统为**固定副本本地运行**（单会话 ≤8 执行专家、单 daemon ≤128MB），无自动 HPA；超限处置为告警 + 限流（Dashboard 轮询 C429001），不横向扩容。
- 扩容方式（人工）：提升单机并发上限（≤8 专家团/会话为硬约束，源于 MVP 单 Main 串行）；完整版 F11 多专家并行编排另议。

#### 3.3.5 容灾切换配置

- 单机器容灾：文件级快照（registry + audit + 会话文件）落**非系统盘**副本，保留 30 天；恢复演练频率半年（@治理组）。
- 跨端容灾：三端 AGENTS.md 同步校验，滞后端阻断对外分发直至一致，避免污染其他端。
- RPO ≤ 5min / RTO ≤ 10min（对齐《系统设计》§7.2.5）。

### 6.1 回滚机制

#### 6.1.3 回滚执行 SOP

| 对象 | 回滚方式 | 预计耗时 | 有损风险 / 数据丢失 |
| --- | --- | --- | --- |
| 插件包 | 三端 market 回退上一 tag + reinstall | ≤ 5 min | 无 |
| registry 配置 | 文件快照回滚（expert-registry.json 版本链） | 小于 1 分钟 | 无 |

#### 6.2.2 Runbook 编写规范

每条 Runbook 按：症状 → 诊断（按顺序，含可观测工具/查询路径） → 缓解（分场景，衔接 §6.1 回滚） → 升级。

#### 6.2.3 RB-01：registry 不可读 / 审计链断裂

- **症状**：AL-01 触发；M2 写入返回读取失败；D-04 大盘 registry 状态红框。
- **诊断**：① 查 `expert-registry.json` 文件权限是否为 0644+lock（R-Sec-001 Z-GOV）；② 校验审计链哈希 `H(prev_hash||event)` 是否连续（R-S-004）；③ 查磁盘是否满（R-S-001 容量）。
- **缓解**：① 从非系统盘快照恢复 registry（RTO≤10min）；② 若仅审计链断，以最近完整快照重建 audit-*.jsonl 并标注缺口；③ 恢复后跑 handoff 审计自测确认覆盖率 100%。
- **升级**：10min 内未恢复 → 升级 @平台组 + 主理人，暂停 prod 写入（仅只读）。

#### 6.2.4 RB-02：多 Main 违例

- **症状**：AL-02 触发；编排启动报错 C403001 多 Main 冲突。
- **诊断**：① 查 `team compose` 定义的 members.main 是否唯一（M3 单 Main 不变量）；② 查 `expert-registry.json` route 是否误配多个 main。
- **缓解**：① 修正 team 定义保留单一 Main；② 重新 `team run`；③ 若已污染会话，重建 `{session}/`（RTO≤5min）。
- **升级**：影响主链路 → 升级 @平台组。

#### 6.2.5 RB-03：Dashboard 后台进程重启超上限

- **症状**：AL-03 触发；D-05 显示 restart_count 达 5；后台进程降级为离线视图（BD-01）。
- **诊断**：① 查 `{session}/.dashboard/heartbeat.json` 是否持续缺失；② 查 daemon 日志（R-O-01）内存/异常；③ 查 model Key 是否从 OS Keychain 读取失败（B3）。
- **缓解**：① 清理 pid 元数据后手动 `dashboard restart`；② 若 Keychain 失败，重注入 model Key（L4）；③ 仍失败则保留离线视图，标注"实时刷新暂停"。
- **升级**：超上限且无法恢复 → 升级 @平台组，安排会话重建。

#### 6.2.6 RB-04：跨专家 handoff 越权拦截激增

- **症状**：AL-04 触发；D-02 越权拦截数 1min 内 超过 10。
- **诊断**：① 查 `handoff consume` 调用方 scope ACL（C403001）；② 查是否有跨责任域引用非公开 handoff；③ 查是否存在恶意/误配专家定义。
- **缓解**：① 阻断越权调用方；② 复核相关 expert 的 scope ACL 定义；③ 必要时 `registry clear-current` 撤回问题专家。
- **升级**：疑似攻击面 → 升级 @治理组 + 安全侧复盘。

#### 6.2.7 RB-05：handoff 审计覆盖率下降

- **症状**：AL-05 触发；D-06 覆盖率 低于 100%。
- **诊断**：① 查 `events.jsonl` 是否漏写 handoff 事件；② 查 M4 审计追加写是否因文件锁失败；③ 查不变量 #5 固定入口是否被绕。
- **缓解**：① 重放缺失 handoff 事件补写审计链；② 修复 M4 写路径；③ 覆盖率恢复 100% 后解除告警。
- **升级**：持续 低于 100% → 升级 @治理组，暂停相关 handoff。

#### 6.2.8 RB-06：Dashboard 时延升高

- **症状**：AL-06 触发；轮询 P99 超过 2s 持续 10min。
- **诊断**：① 查 `progress.json`/`events.jsonl` 文件大小是否接近 50MB 上限（R-S-002）；② 查 daemon 内存是否接近 128MB；③ 查本机 CPU/IO。
- **缓解**：① 清理滚动事件（30 天窗口）；② 降低轮询频率（不低于 2000ms 限流）；③ 会话重建释放状态文件。
- **升级**：资源持续紧张 → 升级 @平台组，评估单机并发上限。
