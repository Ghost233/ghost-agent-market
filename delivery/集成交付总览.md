## 3. 术语统一结果（跨文档强制一致）

| 术语 | 统一定义 | 备注 |
| --- | --- | --- |
| Expert（专家） | Owner 责任域（ACL/Capsule）+ Worker 执行语义（binding/verify）+ 技能挂载 + 模型 profile + 长期线程归属 的单一实体 | 三类子类型：执行专家 / Review 专家 / Dashboard 专家（持有后台进程） |
| 元角色 | Main / Supervisor / Review（协调与审查，不并入 Expert） | 单 Main 不变量保留 |
| expert-registry | 治理底座（原 owner-registry 改名 + 字段合并） | ACL / handoff / Capsule / Worker-binding 统一承载 |
| `{session}/` | 会话级 tenantId 隔离载体 | 含 progress.json / events.jsonl / .dashboard/heartbeat.json |
| OS Keychain | 本系统 KMS 落地实例（macOS Keychain / Linux 0600 文件） | 替代云 KMS |
| Z-* 安全区 | Z-PUBLIC(0644) / Z-GOV(0644+lock) / Z-STATE(0644·0600) / Z-WRITE(0700) / Z-KEY(0600) / Z-DAEMON(0600) | 安全组 → 文件权限映射（两侧完全一致） |
| 密钥分级 L1~L4 | L1 公开 / L2 内部 / L3 敏感 / L4 高敏；**L3/L4 90 天轮换** | 权威在 security-architect，platform 仅引用 |
| 审计字段 | actor / ts / resource / action / hash / session_id | 哈希链不可篡改，保留 **≥1 年** |
| WAF / VPC | **N/A**（本地插件无公网入口 / 无虚拟网络） | 两侧一致标注 |
| Dashboard 后台进程 | M5 dashboard-daemon.mjs：5s 轮询 / 15s 看门狗 / 45s 判 UNHEALTHY / ≤5 次重启 / 优雅回收（无孤儿） | 只读 progress.json / events.jsonl 固定入口 |

## 4. 冲突裁决清单（G3→G5 已解决）

| 序号 | 冲突点 | 各方立场 | 主理人裁决 | 落地 |

| C1 | worktree/ 文件权限 | 部署侧 0700 vs 安全侧初稿 0600 | **0700**：worktree/ 为目录，执行专家需进入并写入，必须带属主执行位（x）；0600 会剥夺 owner 遍历权 | 安全侧已改为 0700（§1.1/§3.1/§3.3.4/§5.1/B2），G5 diff 第 2 项通过 |
| C2 | Dashboard 是否完整设计 + 专职专家 | 原始诉求字面要求合并 Main/Supervisor/Worker/Owner | 按 D1 仅合并 Owner+Worker→Expert；Dashboard 由专职专家持有后台进程（G3 反馈） | 高层 §4.5 / 系统 §3.2.M5 / UserStory US-5 |
| C3 | 审计保留期 | 安全侧设为权威 ≥1 年 | 平台侧保留期须 ≥ 安全侧；双方均 ≥1 年 | 部署 §7.3 / 安全 §7.2，G5 diff 第 5 项通过 |
| C4 | 跨专家 handoff 治理 | 原跨 Owner 不变量 | 平移为"跨专家只消费公开 handoff"，审计 100% 留痕 | 系统 §3.2.M4 / 部署 §2.2.6 / 安全 §1.2 |
| C5 | 三端同步一致性 | 强一致可能阻断 ZCode 单端优化 | AGENTS.md 规则：滞后即阻断分发；单端差异经独立演进说明声明（F10/F12） | 高层 §2.5 / 系统 §6 / UserStory US-4 AC-3 |
